## 0. 门槛 B 的总判定原则

> **门槛 B 由多个互补证据组成，不靠单项通过。**
> 核心命题：当模型只有任务描述、没有对应实现源码时，duty 监督能否帮助它生成符合任务目标、对需求变化敏感、又不依赖单一实现方式的工作流规划。

任何单一检验通过不构成门槛 B 通过；四项检验（B1–B4）须全部给出明确读数，并由 owner 综合裁定。

## 1. 基础定义（冻结）

### 1.1 什么是"独立任务"

一个任务集满足独立性，当且仅当：

1. **生成独立**：任务文本不由本 GEE 语料的实现代码摘要/反写生成；
2. **意图先在**：存在证据表明任务目标先于（或独立于）任何具体实现被确定；
3. **来源可审计**：任务出处有记录，可核查第 1、2 条。

分层标注：

- `independent_verified`：S4 人写任务（撰写时不可见任何实现）；
- `independent_claimed_unverified`：S2 外部数据集，独立主张待适用性审查；
- `derived_from_code`：G0 全部任务，**永远不作为独立性证据**。

### 1.2 什么是"正确的职责序列"

- duty 序列**不要求与参考实现一一对应**；
- 判定单位是逐阶段：每个 duty 须满足 (a) 服务于任务目标，(b) 顺序有任务内依据或合理工作流逻辑，(c) 不引入任务未要求且不可辩护的实现细节；
- **允许多个正确答案**：不同但都合理的分解路径均记 correct；评分规程须预注册"可接受变体"的判定规则；
- 信息不足或任务矛盾时，正确行为是标注 uncertainty，而非擅自补全。

### 1.3 依赖变化原则

删除/新增一个职责后，下游职责可因依赖关系合理变化。判定分三类，独立计分：

- `necessary_change`：预期变化的职责确实变化；
- `irrelevant_stability`：不应变的职责未无故改变；
- `dependency_propagation`：下游职责随必要依赖的改变而调整，且调整本身合理。

## 2. B1 — 独立任务分解测试（修订后）

- 输入：`independent_verified` 或 `independent_claimed_unverified`（经 S2 适用性审查通过）的任务；
- 模型可见输入：**仅任务文本**（T 条件；T 是核心评测条件，见 B4）；
- 判定：按 1.2 的逐阶段规则，允许多正确答案；
- 报告：逐阶段 correct/partial/incorrect + uncertainty 使用率；
- **通过条件（候选阈值，冻结前须经 owner 确认）**：necessary 阶段 correct 率 ≥ 80%，且 incorrect 中"引入任务未要求的实现细节"占比 ≤ 20%。小样本时报告 Wilson 置信区间，不做点估计断言。

## 3. B2 — 最小变更敏感性（判据修订）

原"diff 恰好落在一个位置"废弃。替换为四判据计分：

1. **必要变化正确**；
2. **无关职责稳定**；
3. **依赖变化合理**（按 1.3）；
4. **矛盾/信息不足可识别**：变更使任务信息不足或冲突时，模型标明不确定性而非补全——此判据**计为通过**而非失败。

执行边界（冻结）：

- 探针数量、每探针的预期变化、可接受变体、失败定义，在运行前**预注册**；
- 原候选阈值 90% 降级为"初步证据阈值"：小样本（≤30 探针）只报告分子/分母 + Wilson CI + 逐探针分类，不宣称泛化；
- 每探针输出四判据的独立读数，不合并为单一分数。

## 4. B3 — G2 增量判别（判据修订）

### 4.1 前置：显式映射表

- 冻结 duty ↔ G2 semantic stage 的映射表，**允许一对多、多对一、unmappable** 三类；
- 每条映射附判定规则（为什么这样映射）；
- unmappable 比例显式报告；
- **边界声明**：若映射需要大量人工裁量，映射后分数差不解释为增量价值。

### 4.2 四栏报告（不是单一分数）

1. **共有信息**：两种表示都能表达的内容（如粗阶段顺序）；
2. **duty 新增**：任务明确要求的因子身份、目标变量绑定、重复段计数等；
3. **duty 仍缺失**：完整分支依赖、多节点汇合等；
4. **不可比样本比例**：映射不确定或无法比较的比例。

### 4.3 通过条件（修订）

> **B3 通过 = 存在可重复测量的增量信息**（第 2 栏非空，且增量信息类型在 ≥2 条开发样本上可一致识别），**而不是** duty 整体分数高于 G2。

## 5. B4 — 复述检测（判据修订，最直接的反循环检验）

### 5.1 实验条件（冻结）

| 条件 | 模型可见输入 | 角色 |
|---|---|---|
| **T** | 仅任务描述 | **核心评测条件**（若最终用法是只输入任务，T 是唯一计入主判定的条件） |
| T+S1 | 任务 + 实现甲源码 | 诊断 |
| T+S2 | 任务 + 实现乙源码（不同实现） | 诊断 |

T+S1/T+S2 是诊断实验，**不能替代 T 的表现**。

### 5.2 实现对的要求

- 两实现经人工核验对应**同一任务目标**（非仅同域）；
- 实现差异允许合理的方法分歧；评价按 1.2 允许多正确答案。

### 5.3 测量项（不是输出相似度）

1. 任务目标改变 → 输出合理改变（与 B2 共享判据）；
2. 任务不变、实现改变 → 输出仍满足任务（T 条件下天然满足；T+S 条件下检查被源码牵引的程度）；
3. **源码独有信息泄漏**：仅由实现提供的信息（如特定波段、特定分类器参数）是否出现在 T 条件输出中——出现即记 `implementation_leak`；
4. **实现细节固化**：任务未指定的必要细节是否被武断固定（应标 uncertainty 或保持抽象）。

### 5.4 判定

- **门槛 B 失败条件**：T 条件下 `implementation_leak` 率高，或输出跟随具体实现而非任务（T+S1 vs T+S2 输出差异显著大于 T 自身稳定性）；
- T+S 条件的读数仅用于归因诊断（信息到底从哪来），不直接计入通过判定。

## 6. S2 候选数据集适用性审查规程（先审查后采用）

对 GeoAnalystBench / AutoGEEval / GISAgentBench 逐项核查，输出适用性表（不构建训练数据）：

| 审查项 | 判定 |
|---|---|
| 任务文本来源 | 独立提出 vs 从代码/参考答案反写；须证据 |
| 输出形态 | 任务完成/代码生成/工具调用/工作流规划；可否转换为 duty 序列评测 |
| 参考答案完备性 | 是否允许多条正确分析路径 |
| 数据污染风险（G0 层） | 与 G0/6 条开发样本重叠检查 |
| **数据污染风险（预训练层）** | 与基座模型预训练语料可能重叠——**与 G0 层污染是不同层次，分别报告** |
| 评分成本 | 不补写大量主观标签能否建立可信判定 |

任一数据集若主要测代码执行而无任务分解可用结构，仍有研究价值，但**不得**未经转换充当 B1 金标准。

## 7. S3 探针规程（设计，不扩量）

- 从 6 条开发样本选 5–8 个任务变更案例；
- 每探针预注册：变更内容、预期职责变化、允许变体、失败定义；
- 用途：**调试评价方法本身**，不产生能力结论；
- 产出的规程若可用，再决定是否扩量。
