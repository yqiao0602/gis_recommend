## 2. 工作包 A：自动化边界检测

解决六脚本试运行中依赖人工的三项检测。

### A1. 外部预绑定检测

- 规则：变量在 snapshot 中有使用但无可定位 `var X =` 声明 → 候选外部预绑定；
- 三分类：`external_prebinding`（确定性）/ `missing_definition`（脚本缺陷）/ `indeterminable`（如动态赋值）；
- 输出：每变量 `{definition_location, first_use_line, classification}`；
- 验收：六脚本回测——AOI/geometry/ftTrain 等已知外部变量全部命中，in-source 变量零误报。

### A2. 死代码 / 后继使用检测

- 规则：变量定义后，遍历 R1 数据流图的可追踪后继（直接引用 + 容器成员 + 函数参数传递），计数 `post_definition_uses`；
- 三分类：`unconsumed`（0 uses，候选死代码）/ `presentation_only`（仅进入展示 API）/ `analysis_chain`（进入计算链）；
- **不用简单文本计数**：必须经由 R1 数据流边追踪，防止字符串同名误判；
- 验收：六脚本回测——pi_all（0 uses）正确判 unconsumed；Fire_Sus（12 uses）正确判 analysis_chain。

### A3. 展示层与分析层分类

- 规则：对 GEE API 建立静态分类表（预注册）：
  - `presentation`：Map.addLayer / ui.Chart / ui.Panel / print / Map.centerObject 等；
  - `export`：Export.image/table/video.toDrive/toAsset/toCloudStorage；
  - `analysis`：其余 core chain；
- 不确定分类进入人工复核队列，不自动判定；
- 验收：六脚本回测——C2 图表缺陷（xProperty 错位）应被归入 presentation 并进复核队列而非分析链。

### A4. 重复边去重（数据质量核对项落实）

- 去重键：`(from, to, use_line, via_operation)` 四元组相同 → 同一条逻辑边，合并保留；
- 同变量对不同操作/不同证据 → **分别保留**，不合并；
- 报告双计：原始证据记录数 + 去重后逻辑边数；
- 验收：六脚本回测——269131 的 40→38 去重正确执行，其余 5 脚本 0 变化。

## 3. 工作包 B：小规模验证样本设计

### B1. 样本量

- **不预设数字**。先完成抽样设计与判据冻结，再由以下约束推出最小样本量：
  - 每类困难场景 ≥5 个脚本（统计下限，支持 Wilson CI 下界报告）；
  - 普通对照脚本 ≥10 个（检测规则在"无困难场景"时的误报率）；
  - 预估 30–60 脚本；最终数字在抽样后由 owner 确认。

### B2. 抽样设计（分层，非随机）

困难场景分层（每层 ≥5）：

| 层 | 特征 | 检测来源 |
|---|---|---|
| L1 外部依赖 | 使用外部库 require / 预绑定变量 | A1 检测器 |
| L2 死代码 | 存在定义后无可追踪后继的变量 | A2 检测器 |
| L3 展示混淆 | 含 chart/可视化/导出混排 | A3 检测器 |
| L4 重复子流程 | 同构代码块 ≥3 次 | 文本模式（如 302840 的 coi 块） |
| L5 多公式/多路径 | 同一变量有多个平行定义或多个公式竞争 | A2 变体检测 |

对照层：不命中 L1-L5 的随机脚本（≥10），验证规则不产生误报。

抽样约束：

- 全部来自 G0 train split（与试点一致）；
- 排除六试点脚本；
- 确定性 seed + 算法 R reservoir（沿用既有模式）；
- 每脚本 pin SHA + 生成脚本 + 产物 hash。

### B3. 人工复核协议

- 每脚本：自动重建 → 人工抽验（≥30% 单元）→ 分歧记录；
- 两人独立标注争用样本的 duty 粒度（检验 inter-annotator 一致性，承接 Step 1 Q3 遗留）；
- 分歧不平均，记录后裁定。

## 4. 工作包 C：扩展验收指标（冻结判据）

| 指标 | 定义 | 判据（候选，冻结前需 owner 确认） |
|---|---|---|
| 审计单元语义恢复率 | 各脚本自身审计分母内恢复比例 | 报告分布（min/median/min CI），不要求 100% |
| 证据支持率 | supported 与 supported_passing_only 分列 | 两态不合并；passing_only 比例如实报告 |
| 实现细节固化率 | misassigned_to_duty / checked_units | **≤5%**（零容忍不可达时的现实阈值；任何单一固化案例须逐条解释） |
| 冲突保留率 | 已登记冲突中被两侧保留的比例 | **100%（零容忍）**；静默调和次数 = 0 即通过，任何一次 >0 即 fail |
| 自动化-人工一致率 | A1-A4 检测器 vs 人工裁定 | ≥90%（候选）；分歧逐条归因 |
| 未决项比例 | unresolved / 总关系数 | 如实报告；不设阈值——高未决率本身是诚实信号 |
| 重复边比例 | 重复记录 / 原始记录 | 如实报告；去重规则执行后应为 0 |
| 人工复核成本 | 每脚本人工时长 | 如实报告，用于评估全库可行性 |

**停止条件**（满足任一即停止扩展并回审）：

1. 冲突静默调和 >0；
2. 固化率 >5% 且无法归因为可修规则缺陷；
3. 自动化-人工一致率 <80%；
4. 抽样中发现六试点未见过的新型失效模式且现有规则无法分类。
