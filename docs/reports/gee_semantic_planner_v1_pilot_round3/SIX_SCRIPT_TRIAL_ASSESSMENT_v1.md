## 3. 压力测试支持的规则 vs 仍有边界问题的规则

### 经压力测试得到支持

1. 双态证据口径（supported / supported_passing_only）——在 3 个未定义变量场景下未失效；
2. 冲突两侧保存、不静默调和——C1/C2/C3 全部按此执行；
3. semantic_merge 与控制流分离——405410 七因子与 269131 五因子两种融合形态都正确分类；
4. 任务枚举顺序不升级为执行依赖——269131 的因子顺序同样只记 task_enumeration_order；
5. dual_role 双重职责——Fire_Sus 单元同时记录"任务命名指数"与"死代码并行公式"；
6. 粒度分离——5 审计单元 → 5 R2 单元（本脚本 1:1，但映射结构保留）。

### 仍有边界问题（登记，不阻塞评审）

1. **外部预绑定的深度**：AOI/image/HP_11_09_2019 的缺失证明规则能诚实记录，但自动化时需检测"snapshot 内无声明"模式——当前靠人工发现；
2. **死代码识别**：pi_all 的"0 后继使用"靠人工计数；自动化需要后继使用计数器；
3. **展示层 vs 分析层的自动区分**：C2 靠任务文本自带提示发现；自动化需要图表/可视化 API 的静态分类规则。
