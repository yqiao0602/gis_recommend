## 2. 四个抽样组（身份必须记录）

| 组 | 入选条件 | 规模下限 | 职责 |
|---|---|---|---|
| L1 外部依赖 | A1 候选数 ≥1（含 require 导入） | ≥5 | 检测器已知困难：外部预绑定三分类 |
| L2 死代码 | A2 unconsumed ≥1（排除纯可视化参数） | ≥5 | 未使用/仅展示/分析链三分类 |
| L3 展示混淆 | A3 presentation 与 analysis 调用共存于同一变量消费链 | ≥5 | 角色共存与复核队列 |
| L4 重复子流程 | AST 检测同构代码块 ≥3 次（如 302840 的 coi 块） | ≥5 | 任务重复 vs 代码复制 |
| L5 多公式/多路径 | 同一变量多个平行定义或竞争公式（A2 变体：重复赋值/多初始化） | ≥5 | 冲突两侧保存 |
| C 对照组 | 不命中 L1–L5 任一判定（分层对照） | ≥10 | 误报率 |
| R 独立随机组 | **Algorithm-R 等概率随机，不以任何检测器结果为条件** | ≥10 | 漏检发现（检测器未识别而脚本实际存在） |

- L1–L5 允许同一脚本命中多层并重复入选；**同时报告各层样本数与去重后脚本总数**；
- "每层 ≥5"仅为探索性覆盖下限，不声称支撑总体统计推断；Wilson CI 下界仅作描述性报告；
- R 组可与 C 组自然重合（随机抽到不命中脚本），但保留独立抽样身份标记，不合并身份。

## 3. 确定性规则

- 候选池按 script id 字典序排序后处理；
- seed = **20261009**（写入脚本常量，与产物一起冻结）；
- 层内选择：按 A1–A4 检测器得分排序（命中数降序、id 升序破并列）取前 N；N 在执行时由 owner 确认（预估总规模 30–60，含重叠）；
- R 组：Algorithm-R reservoir，k=10，唯一随机流（与层内选择共享 seed 但独立流实例）；
- 全程零人工挑选；任何执行期替换（如源码缺失）记录替换理由并保持 seed 流不变。

## 4. 执行边界

- 本方案只冻结设计与脚本；**本阶段不运行抽样**；
- 实际执行需 owner 单独批准；批准后一次性运行 `scripts/build_expansion_validation_sample_v1.py`，输出样本清单 + 每脚本 SHA + 产物哈希账本，样本清单冻结后不可再改（改动须重开裁定）。
