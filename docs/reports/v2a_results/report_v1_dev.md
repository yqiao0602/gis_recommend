## 3. 两个重大诊断发现（本轮最有价值的部分）

### 3.1 主要损失不是"选错算子"，而是**重复失控 + 名称格式错误**

**(a) 重复失控**：44/120 parse 失败中 **42 行跑满 512 token 上限**，且输出尾部是同一算子无限重复（如 `native:extractbydistance` 连续 20+ 次）。35% 的 dev 行因此产出非法 JSON。这与 M3-P1 的 runaway 同型——**序列终止控制是跨架构、跨输出空间的共同短板**。可解析行的生成长度 p50=73 / p90=189，说明正常行并不长。

**(b) 名称格式错误**：预测算子中 **39%（93/236）不在 1,291 算子 catalog 内**，但绝大多数是**真算子的截断/前缀错误**：
```
native:reproject      → native:reprojectlayer
native:reclassify     → native:reclassifybytable
native:merge          → native:mergevectorlayers
native:gdal:translate → gdal:translate      （provider 前缀叠错）
gdal:ras              → gdal:rastercalculator（截断）
grass:v.clean         → grass7:v.clean
```
**含义**：模型常常**知道该做哪个操作，只是写不对算子 ID**。名称规范化（近邻匹配）后 A 的 operator precision 从 0.326 → **0.508**（+56%），F1 0.281 → 0.301。这直接指向一个**不改变架构的改进**：catalog 约束解码 / 名称规范化层——且它属于 V2a 原生空间内（无 L3、无 bridge）。

### 3.2 预测系统性少报

预测算子实例 236 vs gold 671（A），中位预测 2 个算子 vs gold 3 个——模型**倾向生成短链**（且伴随 35% 的重复失控行，说明是双峰：要么太短要么停不下来）。这与"gold 链含 extraction 产生的重复算子"有关（gold 中同一算子出现多次），需在 test 报告中按 gold 重复度分层复核。

| 事故 | 代价 | 修复 |
