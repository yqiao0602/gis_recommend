## 2. 损失归因（本轮最重要的结果）

### 2.1 两套口径必须分开报（此前只报了条件口径）

| 口径 | 含义 | A op F1 | A link F1 | B op F1 | B link F1 |
|---|---|---:|---:|---:|---:|
| **条件**（仅可解析行） | 模型一旦产出合法 JSON 的质量 | **0.388** | 0.431 | 0.338 | 0.438 |
| **端到端**（不可解析行按零召回计） | 实际可用性 | **0.232** | 0.238 | 0.184 | 0.213 |

**两者之差 = 截断失控的代价**：A 的 operator F1 从 0.388 掉到 0.232（**损失 40%**），B 从 0.338 掉到 0.184（损失 46%）。

### 2.2 三个损失源按大小排序（dev，canon 名称口径）

| 损失源 | A 的代价 | 证据 |
|---|---:|---|
| **① 重复失控截断** | F1 0.388 → 0.232（−0.156） | 42/120 行（35%）跑满 512 token，且这些行 op P/R = **0.000/0.000**（零产出）；B 更差 64/147（44%） |
| **② 算子名损坏** | F1 0.301 → 0.388（−0.087，条件口径） | 51% 预测实例越界，几乎全为真算子的截断/前缀错误（`native:reproject`→`reprojectlayer`、`gdal:ras`→`rastercalculator`） |
| **③ 链结构能力** | 短链 F1 0.478 vs 长链 0.338（−0.140） | gold ≤3 步 vs >3 步分层（非截断行内） |

## 3. 结论与下一步优先级

**V2a 的核心问题已回答**：直接生成 QGIS 原生 `processes + links`（无 L3、无 bridge）是**可行的**——A 在条件口径下达 op F1 0.388 / link F1 0.431，且 link 指标是 V1 体系无法测量的结构能力。**但当前实际可用性被序列终止问题腰斩**。

**按杠杆大小的改进优先级**：

1. **序列终止控制**（最大杠杆，+0.15 量级）：catalog 约束解码 / 重复惩罚 / no-repeat-ngram / EOS 强化。注意 M3-P1 已有同类解法（`eos_lambda` 加权 SFT）可复用；且这属于**解码与训练目标层面**，不改变数据或架构。
2. **算子名规范化**（+0.087）：后处理近邻匹配（零成本，立即可得）或 catalog 约束解码（训练/解码层，根治）。
3. 长链能力（>3 步）：需要更多长链监督或过程监督——但仍受 ① 制约，应后置。

**与 V1 的关系（口径纪律重申）**：V2a 是原生算子空间，V1 是 L3→bridge。M3-P1 0.1605 / M3-P2-T1 0.1991 不构成 V2a 门槛。架构级定论需在同一 benchmark v0.2.1 上对照（下一步）。
