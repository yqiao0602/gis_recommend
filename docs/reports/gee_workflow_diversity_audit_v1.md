# GEE 工作流多样性审计 v1：11.7 万链是 10 万个工作流，还是几百个模板？

日期：2026-09-17
前置：`gee_data_asset_audit_v1.md`（e92cd5e，资产盘点）
问题（owner 提出）：117,735 条唯一链是真实 workflow diversity，还是几千个模板 × 上百变体？script diversity ≠ workflow diversity。这直接决定路线 ②（H1-H4）的采样与阶段设计。

---

## 1. 结论（先行）

**既不是 10 万个独立工作流，也不是几百个模板——是约 2.4 万个真实推理工作流（保守）到 6.8 万个唯一 API 链（宽松），多样性是真的，但一半语料是 load→export 琐碎脚本。**

```
分层漏斗（方法级规范化：MOD09A1.filterDate.map → filterDate→map，剥离变量前缀）：

191,210 描述∩链
  └─ ≥2 真实算子（含用户函数）          180,460
       └─ ≥2 真实 ee.*/Export.* API    145,479        ← ee-API 口径池
            ├─ 唯一精确链                 67,924（74% 单例簇）
            ├─ 唯一算子集合（无序）        52,626
            └─ 推理分层（核心族 = filter/map/reduce/select/classify/math/mask/join）：
                 0 核心族（load→export）     42,624   29.3%  ← 对推理监督近乎无用
                 1 核心族                  58,624   40.3%
                 ≥2 核心族（推理层）        44,231   30.4%
                      └─ 唯一精确链        24,499   86 任务类型
```

## 2. 五个测量发现

### 2.1 多样性是真的（回答核心问题）

- ee-API 口径唯一链 **67,924**，其中 **74% 是单例簇**（该链只出现一次）；≥100 成员的模板簇仅 58 个。
- 最大簇 1,427 成员，但前 10 大簇全部是 2-4 元素的退化链（`ee.Image -> ~f` 之类），不是长模板复制。
- **模板镜像风险集中在琐碎短链，长链几乎不重复。** 不是"500 模板 × 100 变体"结构。

### 2.2 描述不是链的镜像克隆（数据增广价值成立）

同簇脚本的描述间 Jaccard 仅 **0.12-0.16**（top-5 簇实测）——同一算子链配的是**不同任务描述**。全库 case 归一化后 179,928/180,460 描述唯一（仅 0.3% 重复）。**「链去重 + 描述保留多版本」策略有效**：模板簇不是浪费，是天然增广。

### 2.3 一半语料是"数据搬运"脚本

推理分层显示 29.3%（42,624）的 ee-API 脚本是 0 核心族（只有 ee.Image/FeatureCollection → Export，无任何分析结构）；40.3% 只有 1 个核心族（单操作如仅 filter）。**推理密集层（≥2 核心族）只有 44,231 条 / 24,499 唯一链**，任务类型 86 个（LULC 21,987 / 植被 6,264 / 农业 4,832 为主）。

### 2.4 算子词汇长尾极陡（规范化是硬前置）

ee 算子词汇 **9,828 个**，但 Zipf 覆盖：13 个算子 = 50% token，300 个 = 90%，3,206 个才到 99%。链里的细粒度方法调用（`MOD09A1.filterDate.select.mean.rename.clip`）必须规范化为 canonical 算子——项目内已有 306 算子的 GEE canonical 映射（306/306 已映射 L3），覆盖率需在转化时实测。**这正好对应 owner §11 指出的 "semantic operation vs implementation-level API operation" 区分。**

### 2.5 链长（ee-API 口径）健康

median 5 / mean 9.3 / p90 17 / p99 67（早期报告的 median 9/mean 22.7 是含用户函数 token 的口径；4,249 的极端值来自循环拼接，需截断处理）。
