## 2. 判定（预注册判据逐条）

### A1+DC：**红线触发 → DC-1 对 A1 FAIL**

- **hit_cap 18.0% → 34.2%（+16.2pp，≈P2 的 +14pp 复现）**——且本次 EOS 每步显式放行。**这证伪了"P2 hit_cap 上升是 EOS 被掩码误伤"的假设**：EOS 合法且可选，A1 依然成批跑马（冒烟 8 行即有 1 例 `extractbylocation` 连发到 cap）。
- op e2e F1 0.267 → 0.216（**−0.051，约束使 A1 更差**）；link 0.283 → 0.214（−0.069）；parse 91% → 80.2%（更多截断行 fail-closed）。
- 按预注册："hit_cap 上升 = 设计缺陷信号 → 记录并转向 DC-2，不调 trie 参数"。

### C0+DC：意外的正向结果（记录为 secondary finding）

- precision 0.435 → **0.518**（+0.083），recall 持平（0.287），**F1 0.343 → 0.370 = C0 迄今最好数字**；hit_cap 仅 +1.8pp、link −0.011（轻微）。
- **同一 mask，对 C0 是净收益（清掉它的非法算子噪声），对 A1 是净伤害**——这个分离本身就是 FA 归因的强佐证：C0 的噪声在"合法性"，A1 的故障在"控制"；mask 只能治前者。

## 3. 机制解读（DC-1 暴露的新事实）

1. **P2 事故假设被证伪**：EOS 合法 ≠ EOS 被选。约束不是通过"堵逃逸口"间接伤停控——而是**直接改变 EOS 的相对竞争力**：trie 把原本流向非法续写的概率质量重新分配到合法算子续写上，EOS 的相对份额被进一步稀释。对分布已被 DAPT 摊平的 A1（FA-D1：NLL 更高、acc 不变），argmax 在"合法地继续"与"停"之间系统性偏向继续。
2. **控制故障不是"逃逸"而是"相对概率"问题**——这意味着纯掩码类干预（删选项）对 A1 结构性无效，甚至有害（封掉逃逸后合法跑马更长、截断更多）。FA 的 Control 归因经 DC-1 反向加强。
3. C0+DC 的正向说明：**mask 对"分布健康"的臂是纯增益**——这为"输出约束适合谁"给出了清晰的边界条件。

## 4. 转交 DC-2 的设计约束（由本结果推出，非参数微调）

DC-2（状态感知 EOS）面对的新事实：**问题不是 EOS 被禁，而是 EOS 相对概率不足**。因此 DC-2 的机制必须是**提升 EOS 相对质量**（状态条件化的 logit 偏置：图结构达到合理终点信号时 EOS boost；以及/或重复状态下的合法算子降权），而非继续扩充掩码。spec 占位条款"结构化 EOS 条件"与本结论一致；具体设计另立 spec，跑前预注册。
