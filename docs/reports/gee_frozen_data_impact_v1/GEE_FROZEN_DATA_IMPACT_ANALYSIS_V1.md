## 1. 缺陷 → 抽取规则映射

审计发现的三个错误族对照生产抽取管线（`gee_source_extractor.py` v2.3.2 → canonicalization → `gee_route2_semantic_workflow_v1.py` 语义投影 → RLE）：

| 错误族 | 审计检测器中的缺陷 | 生产抽取管线对应路径 | 是否污染冻结数据 |
|---|---|---|---|
| **F-A** UI/图表消费对象判 analysis | `ui.*` 命名空间 fallback 把纯展示消费判为 analysis | 生产抽取器 L1095-1096：`Map./ui./Chart./print` 前缀**显式分类 presentation**（`_ORIGIN_PRESENTATION`），presentation origin 调用不进入 canonical 链 | **否**（实证 §2） |
| **F-B** presentation 调用内的统计输入 | 无法识别 presentation 调用内部的统计语义 | 链构造为扁平调用序列；presentation 调用不产生节点，其实参亦不产生节点 | **否（结构上不适用）** |
| **F-C** 未消费/死分支 | pre-v1.0 unconsumed 定义 + 静态/语义边界 | 生产抽取器**从未包含未消费过滤**——按序抽取全部调用，死分支调用照常进入链 | **是（设计属性，非检测器缺陷）**，量级见 §3 |

关键结论：审计的 A1–A4 检测器是**为本轮审计新建的变量级工具**，不是生产抽取器；F-A/F-B 是审计检测器的实现缺陷，生产管线用不同的（更简单的显式前缀）规则，**不存在同类缺陷路径**。

## 2. F-A/F-B 实证核验（20,000 行冻结快照扫描）

- 语义链词表**恰为 30 类**，无任何展示类目；初筛正则命中的"展示样 token"全部为 `OTHER_UNMAPPED`（含子串 "UNM**APPED**"）的假阳性；
- canonical 链中 `Map.addLayer` / `ui.Chart` / `print` / `Map.centerObject` / `ui.Panel` 计数**全部为 0**——presentation 调用在抽取层即被排除，从未进入监督目标；
- `EXPORT_OUTPUT`（912+440 次）是 30 类设计内的合法类目，非展示污染。

**裁定框架第 1、2 项结论：F-A/F-B 对冻结数据零污染，不构成重构理由。**

## 3. F-C 量级（24 脚本人工审计外推）

未消费变量（v2 终态标签）占全部声明变量比例：

- 总体 **69/676 = 10.2%**；中位约 11%；范围 0%（6 个脚本）– 37.5%（45485）；
- 高占比脚本集中在困难层与 R 组（100110/100133/216850/217669/35821 均 ~14–19%），对照组普遍 0%；
- 这些变量的定义调用产出的 canonical token **存在于冻结链中**，构成监督链里的"噪声步"。

**定性**：这不是本轮审计检测器造成的缺陷——生产管线自始就没有死代码过滤（六脚本试点已将死分支记录为"工作流噪声"的设计属性）。它对训练的实际危害（噪声步是否损害任务分解学习）是**实证训练问题**，无法由本审计单独回答。
