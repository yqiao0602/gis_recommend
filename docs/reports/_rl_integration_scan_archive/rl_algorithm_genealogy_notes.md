# RL 算法族谱笔记（理论主干）——强化模型路线调研 ①

日期：2026-09-18
定位：RLVR-P0 前置理论笔记。目标不是数学完备，而是**每个算法"解决什么问题、付出什么代价、何时该选它"**，并全部映射回我们的 L3 链生成场景。笔记结构：概念速查 → 族谱演化 → 分族详解 → 三大核心问题 → 选型结论。

---

## 1. 必懂概念速查（5 个术语 + 在我们系统里的对应物）

| 术语 | 严格含义 | 直觉 | 在我们系统里的对应物 |
|---|---|---|---|
| **policy（策略）** | π_θ(a\|s)：从状态到动作分布的映射，就是被训练的模型本身 | "模型在每个位置上下一个 token 的概率分布" | M1 的 decoder（132 词表上逐步分布）/ M3 的 Qwen（生成 L3 链文本） |
| **rollout（采样轨迹）** | 从当前 policy 采样一条完整生成（含最终奖励） | "让模型实际做一道题，做完打分" | 采样一条完整 L3 链 → set_f1/I-O 契约打分。**我们的 rollout 极便宜：~5-13 token/条** |
| **advantage（优势）** | A(s,a) = 实际回报 − 基线（baseline），衡量"这个动作比平均水平好多少" | "组内排名信号"：平均分没有学习信息，**相对好坏才有梯度** | 同一任务采样 G 条链，set_f1 高于组均值 → 正优势。这也是"多解 gold"场景的救星：不需要唯一标准答案，只需要相对排序 |
| **reference model（参考模型）** | π_ref：冻结的 SFT 初始模型副本，只算 KL 不更新 | "防止学生跑飞的锚" | M3-GRPO 中锚定在 M3-P2-T1 的 SFT checkpoint；M1-DPO 中隐含在损失构造里 |
| **reward shaping（奖励塑形）** | 在主奖励上加辅助项（长度、格式、过程分）引导学习 | "给分规则里加小项" | 风险区：长度/EOS 塑形在组相对框架下会产生 phantom advantages（2609.13866）。ComfyUI-R1 的答案：用**二元 veto 门**管结构，不用连续塑形项 |

一个容易混的点：**policy 是"正在变的模型"，reference 是"冻结的旧模型"，reward 是"出题打分的程序"**——三者是不同的对象。RL 训练的唯一目标 = 调整 policy 让 rollout 奖励变高，同时（通过 KL）不让它离 reference 太远。

## 2. 族谱演化主线（每个算法的诞生动机）

```
TRPO (2015)          困难：策略更新步子太大会崩
  └→ PPO (2017)      解法：用 clip 代替硬约束，好实现 → 成为通用默认
       └→ PPO-RLHF (InstructGPT 2022)   加上 RM + critic + KL，对齐 LLM → 太重（4 个模型同时在显存里）
            ├→ DPO (2023)   直接砍掉 RM 和采样：偏好对 + 封闭式损失 → 离线、稳定、便宜
            │     └→ IPO / KTO / ORPO / SimPO (2024)  修 DPO 的过拟合/无负例/参考模型依赖
            └→ RLOO (2024)  砍掉 critic：用组内其他样本的均值当基线（REINFORCE Leave-One-Out）
                  └→ GRPO (DeepSeekMath 2024 → DeepSeek-R1 2025)  RLOO 思路 + 组内 mean/std 归一化 + KL 项
                        ├→ Dr.GRPO (2025)   修 GRPO 自带的两处归一化偏置（长度偏置）
                        ├→ DAPO (2025)      修长 CoT 下的熵塌缩：clip-higher + 动态采样 + token 级损失
                        └→ GSPO (Qwen3 2025) 修 token 级重要性比的数值不稳：改成序列级 clip
```

演化逻辑一句话：**PPO 太重（4 模型）→ 两个方向的减法：DPO 砍采样（离线化），RLOO/GRPO 砍 critic（蒙特卡洛化）→ GRPO 系在长序列 RLVR 实践中暴露新问题 → DAPO/GSPO 打补丁。**

## 3. 分族详解

### 3.1 PPO（Proximal Policy Optimization）——族的起点

- **机制**：clip 后的重要性比目标 + GAE 优势估计 + 独立 value network（critic）。
- 重要性比：ratio = π_θ(a|s)/π_old(a|s)，衡量"新策略相对采样策略把这个动作的概率改了多少"。目标 = min(ratio·A, clip(ratio, 1-ε, 1+ε)·A)——**把单步更新幅度限制在 [1-ε, 1+ε]**，这就是"proximal"（近端）的含义。
- **要 critic 的原因**：GAE 需要逐步价值估计来降方差。对 token 级稀疏奖励（整条链只有一个 set_f1 分），critic 要学会预测"这条链走到一半还能拿多少分"——难训练且翻倍显存。
- **代价**：4 个模型同时在线（policy、critic、reference、reward/RM），工程最重。
- **适用**：密集奖励、长序列、奖励信号噪声大的场景。**对我们过重，不选。**

### 3.2 DPO（Direct Preference Optimization）——离线减法路线

- **机制**：从 KL 约束 RLHF 的解析最优解出发（π* ∝ π_ref·exp(r/β)），反解出 r 代入 Bradley-Terry 偏好模型，得到**封闭式分类损失**：直接在 (chosen, rejected) 偏好对上训练，不需要 RM、不需要采样、不需要 critic。
- **性质**：**off-policy**——在固定的偏好数据集上反复训练，像 SFT 一样简单稳定；超参少（就一个 β）。
- **局限（关键）**：
  1. **能力上限 = 偏好对数据的上限**。它只能学会"在已有候选中偏向好的"，**不能发现数据里没有的新解**。
  2. 分布偏移：数据是旧策略生成的，训练久了与当前策略脱节（缓解办法：iterative/online DPO——每轮用当前策略重新采样构对）。
- **适用**：有可靠的偏好来源（人工标注/强验证器打分）+ 想要最小工程改动 + 单卡。**M1-DPO 档即此：beam top-k × composite score 构对，全部基础设施现成。**

### 3.3 RLOO / REINFORCE 族——蒙特卡洛减法路线

- **机制**：同一个 prompt 采样 G 条，**每条的优势 = 自身奖励 − 其他 G-1 条的均值**（Leave-One-Out）。基线无偏且不需要学出来的 critic。
- **代价**：方差比带 critic 的 GAE 高（纯蒙特卡洛），需要更多采样补偿；没有 KL 项的版本容易漂。
- **意义**：证明了"砍 critic 可行"——GRPO 的直接前身。

### 3.4 GRPO（Group Relative Policy Optimization）——当前 RLVR 默认

- **机制**（ComfyUI-R1 笔记 §3.4 已核对过公式）：
  - 每个任务采样 G 条 → advantage = (r_i − mean)/std，**组内即基线**；
  - PPO 式 clip 目标 + 显式 KL 项（k3 估计器，β≈0.001）锚定 reference。
- **相对 PPO 砍掉了什么**：value network（G 条采样的组统计量替代）+ 独立 RM（规则可验证奖励替代）。显存和工程量减半以上。
- **已知问题（后面两个补丁的靶子）**：
  1. std 归一化偏置：组内全对/全错 → std→0，优势爆炸；且"更难的题"（普遍低分）反而拿更小的有效优势；
  2. 长度偏置：损失按 token 归一化 → 长回复被摊薄；
  3. 组内同分（全对或全错）→ 优势全 0，该样本零梯度（采样浪费）。**这个对我们特别重要：多解 gold + 组小 → 同分概率不低。**
- **适用**：规则可验证奖励 + 中短序列 + 单/少卡。**M3-GRPO 档的默认选择。**

### 3.5 DAPO / GSPO / Dr.GRPO——GRPO 的三个补丁

| 补丁 | 治什么病 | 核心改动 | 对我们 |
|---|---|---|---|
| **Dr.GRPO** | GRPO 的 std 归一化制造假优势（难的题优势被压小；1/长度 归一化偏置长序列） | 去掉 std 除法、去掉长度归一化，advantage = r − mean | **值得直接采用**：一句话改动的稳健版 GRPO |
| **DAPO** | 长 CoT RL 的熵塌缩（策略越来越确定→多样性枯竭→学不动）；全对/全错样本浪费采样 | ① clip-higher（解耦上下 clip，放宽上界 ε_high 鼓励探索）② 动态采样（过滤全对/全错组）③ token 级损失 ④ 截断软惩罚 | ②直接相关（我们同分浪费问题）；①在探索不足时再考虑；长 CoT 项与我们短链关系不大 |
| **GSPO** | token 级重要性比数值噪声大（MoE/长序列尤甚）→ 训练不稳 | 重要性比与 clip 全部**提升到序列级**（几何平均） | 若用 Qwen3 系基座可关注；Qwen3.5 场景保持留意即可 |

> 注意：DAPO 还**去掉了 KL 项**（认为它阻碍探索）。这说明 KL 是可调的权衡不是铁律——但 ComfyUI-R1（我们的直接先例）保留了 β=0.001 的弱 KL。第一轮从保守配置开始。

## 4. 三大核心问题专节

### 4.1 on-policy vs off-policy：数据新鲜度 vs 样本效率

| | on-policy（PPO/GRPO/RLOO） | off-policy（DPO 及其族） |
|---|---|---|
| 训练数据 | **每一步都用当前策略现采样**，用完即弃 | 固定数据集（旧策略或人工生成的偏好对）反复用 |
| 数据利用率 | 低（每条 rollout 只贡献一次梯度） | 高（可以跑多个 epoch） |
| 稳定性 | 好（无分布偏移） | 有分布偏移风险（数据代表的是旧策略的行为） |
| **探索能力** | **能发现数据里不存在的新解**（只要奖励函数认） | **上限 = 数据集里已有的候选** |
| 工程复杂度 | 高（rollout 引擎 + 训练引擎协同） | 低（等同 SFT 管线） |

**对我们的深层含义**：这是 M1-DPO vs M3-GRPO 的本质分野。我们的 gold 是**多解**的（metric contract 已声明）——GRPO 的 on-policy 探索有理论机会发现 gold 之外的**新有效链**（奖励只要求过验证器，不要求匹配 gold），这是 DPO 结构上做不到的；而 DPO 永远只能在 beam 候选里重排。**探索能力是我们选 on-policy 的最重要理由**，比省 critic 更重要。

### 4.2 GRPO 为什么砍 critic？

1. **RLVR 场景下 critic 不好学**：奖励稀疏（整条链一个分）+ 多解（同样的前半链，后半不同结局），价值函数要拟合的目标方差极大。
2. **组统计量是免费的无偏基线**：同一题采样 G 条，组均值就是"这道题的期望分"的蒙特卡洛估计——恰好是 critic 想估计的东西，不用神经网络学。
3. **省一半模型**：critic 通常与 policy 同尺寸，砍掉 = 显存/算力近半。这是 23GB A10 单卡上 GRPO 可行的先决条件。
4. **代价**：方差更高（蒙特卡洛 vs 学习出的基线），靠加大 G 和动态采样补偿。

### 4.3 KL 约束防什么？

两个失败模式，KL 是同一味药的两用：

1. **Reward hacking**：奖励函数永远不完美。无约束策略会漂向"刷分捷径"——例如学到某种碰巧拿高 set_f1 的模板链，或利用 I/O 契约的边角案例，生成 reference 分布里几乎不可能出现的畸形输出。KL 把策略按在 reference 附近，**让"钻空子"的路径保持低概率**。
2. **灾难遗忘 / 能力退化**：RL 只优化一个标量奖励，其他能力（语言流畅性、格式多样性）没有梯度保护，会静默退化。KL 项是"别把 SFT 学到的东西丢掉"的软约束。
3. **反方观点（DAPO）**：KL 太强会锁死探索——尤其在奖励本来就稀疏的 RLVR 里，弱 KL（β=0.001 量级）或干脆去掉（DAPO）是近年趋势。
4. **实践定式**：**β 从小开始（1e-3），监控 KL 曲线**——KL 突然飙升 = reward hacking 或训练不稳的早期信号；这应进我们的 RLVR-P0 监控指标清单。

## 5. 选型结论（理论 → 我们的路线）

| 决策点 | 结论 | 理论依据 |
|---|---|---|
| M1（自研小 decoder） | **DPO**（task_plan 既定"可选 DPO"） | off-policy 稳定、偏好对由现成 beam×composite 构造、单卡友好；M1 无预训练先验，on-policy 探索的收益也有限（探索空间受限于弱 decoder 本身） |
| M3（Qwen-9B SFT 后） | **GRPO**（建议 Dr.GRPO 变体起步） | RLVR 标配；砍 critic 是单卡可行前提；**on-policy 探索可发现 gold 之外的新有效链**——多解 gold 场景的核心增值；同分零梯度问题用动态采样思路 + 分层奖励（veto 门 + set_f1）缓解 |
| PPO | 不选 | 4 模型 + critic 训练难度，与 23GB 单卡和多解稀疏奖励双重不匹配 |
| DAPO/GSPO | 不作为第一轮，作为备选补丁 | 先跑通保守 GRPO（弱 KL + G=4-8 + 短序列），暴露出熵塌缩/同分浪费再上对应补丁 |
| KL | 保留，β=1e-3 起步，KL 曲线进监控清单 | ComfyUI-R1 先例 + reward hacking 防御；DAPO 去KL是长CoT语境，我们短链不需要那么激进 |

**一句话总结**：DPO 是"给已有候选重排的离线分类器"，GRPO 是"边采样边探索的在线优化器"；我们两条都要——M1 用 DPO 是因为基础设施与算力匹配，M3 用 GRPO 是因为**探索多解空间正是我们缺的能力**。
