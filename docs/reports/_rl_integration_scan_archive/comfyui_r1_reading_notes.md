# ComfyUI-R1 精读笔记（方法 + 奖励章节逐节）

日期：2026-09-17
来源：`papers/2506.09790_ComfyUI-R1_Workflow_Generation.pdf`（ACL Asia "SA Conference" 2025 版本，正文 11 页）
定位：与我们"NL 任务 → L3 算子链"最同构的 RL 先例。本笔记逐节拆解其方法设计，并标注对 RLVR-P0 的迁移含义。

---

## §3 总体架构：两阶段 pipeline

**冷启动 SFT（§3.2）→ RL/GRPO（§3.4）+ 细粒度混合奖励（§3.3）**。

输入设定：user query（任务描述）+ **预检索的候选节点集 V_cand** → 模型推理（选节点 → 规划原理 → 生成 workflow 代码）。
> 注：主实验给 V_cand（测的是"给定候选的推理能力"），端到端实验（§4.5，ComfyBench）不给，用 embedding 检索 top-3 workflow 聚合节点。**这个"检索缩减输出空间"的设定与我们 beam/L3 候选的架构位置一致。**

基座：**Qwen2.5-Coder-7B-Instruct**（代码基座，非通用 instruct——因为输出是代码表示的 workflow）。

## §3.1 知识库构建

| 步骤 | 数字 | 细节 |
|---|---|---|
| Node KB | 40K → **7,238 节点** | 去重 → 过滤无输入/输出参数的节点；无文档节点用 Claude 3.5 分析 GitHub 仓库生成文档（节点类型/用法/参数含义） |
| Workflow KB | 27K → **3,917 workflows**（均值 21 节点/条） | 过滤链：不满足执行标准 → 精确去重 → **JSON↔代码双向转换可逆性验证**（写了解析器又写了反向解析器，只保留两个方向都能转的）→ 删无关节点（"Anything Anywhere"）→ 删除 Node KB 外节点 |
| 描述补全 | — | 社区工作流缺功能描述 → GPT-4o 结合社区文本+结果截图生成 |

> **迁移含义①**：JSON↔代码双向可逆性验证 = 我们"确定性转换 + 反向校验"纪律的直接对应物；他们清洗后留存率 14.5%（3,917/27K），与我们 authority 留存率量级一致——说明"社区原始数据 ≠ 训练数据"是普遍规律，我们的严格门禁不是过度设计。

## §3.2 SFT 冷启动

**数据构造三步**：
1. **模拟节点检索**：V_cand = V_gold ∪ V_random，其中 |V_random| = ⌊0.8·|V_gold|⌋——**每条 gold workflow 配 80% 比例的干扰节点**（相对 gold 规模）。
2. query 与设计原理 rationale 用 Qwen-Max/Claude 3.5/GPT-4o 生成（3,717 train / 200 test workflows → **11,140 train / 600 test 样本**，即每条 workflow 多次采样不同 V_cand 做增广）。
3. 输出目标 = 长 CoT 序列 s = [V_g（选中节点）, r（设计原理）, c（workflow 代码）]，标准 next-token CE。

**输出格式**（标签结构化）：`<selected_nodes>…</selected_nodes>` → `<design_principle>…</design_principle>` → `<workflow>…</workflow>`（Python 风格函数调用，拓扑序）。

> **迁移含义②**：**80% 干扰项 + 多次采样增广**对我们直接可用——M3 的 prompt 可加入"L3 候选清单"模式（模拟我们 M1 beam 的信息结构），8,817 行 paper_v1 train 可同法扩成多倍 SFT 样本。
> **迁移含义③**：消融证明**代码表示 > JSON 表示**（F1 0.60 vs 0.57，因代码更紧凑且携带逻辑结构）——我们的 L3 链输出格式设计同理：结构化序列（类代码语法）应优于纯 JSON 文本。

## §3.3 奖励设计（核心章节）

论文明确动机："数学任务有唯一正确答案可用简单规则奖励；workflow 生成有多层复杂性（幻觉节点、格式、DAG 结构）"→ 设计**四个分量的 rule-metric hybrid reward**：

### 四个分量

| 分量 | 公式 | 性质 |
|---|---|---|
| 格式 R_format | 0（标签齐全可解析）/ **-1** | 规则门 |
| 结构 R_DAG | 0（workflow 部分解析成合法 DAG）/ **-1** | 规则门 |
| 节点保真 R_fidelity | 0 / **-1**（两种触发：①选中节点不在 V_cand=幻觉；②selected_nodes 声明的集合 ≠ workflow 代码实际用的集合=前后不一致） | 规则门 |
| 节点选择精度 R_correct | **|V_p ∩ V_g| / |V_g| − 1**（gold 节点集召回率，平移到 [-1, 0] 区间） | 连续度量 |

### 合成：veto 机制（公式 6）

```
R_final = -1                          若 R_format/R_DAG/R_fidelity 任一为 -1（一票否决）
        = (4 + R_correct) / 4.0       否则（取值 [0.75, 1.0]）
```

**关键设计解读**：
- **有效输出的最差分 0.75，无效输出 -1**——两者间隔 1.75，保证任何"结构坏但节点碰对"的输出不可能获得正优势；硬约束优先于度量。
- R_correct ∈ [-1,0] → R_final ∈ [0.75, 1.0]：**有效输出内部只用节点召回率区分高下**。
- **注意：RL 奖励不含边/顺序信息**——边的正确性只在评测（LIS/MCIS）里，训练奖励只管"选对节点集 + 结构合法"。这是个重要简化：结构合法性用二元门管住，序列细节交给模型从 SFT 先验里带出来。
- 奖励**全部规则计算，零执行、零 RM、零标注**——rollout 奖励成本≈0（与我们 set_f1 + Neo4j 契约完全同性质）。

> **迁移含义④（对我们最重要）**：veto 式分层奖励 = 我们两级奖励的直接模板：
> - 我们的规则门：L3 码合法性（132 词表内）+ DAG 序列化合法 + （可选）I/O 类型粗契约（Neo4j vector/raster）
> - 我们的连续度量：set_f1（对标其节点召回）+ 链长/EOS 项（谨慎，phantom advantage 风险）
> - 他们"边不进奖励"的简化对我们同样可用：**L3 序列顺序可不进奖励**（只管集合+结构门），顺序能力靠 SFT 先验——这直接绕开我们"多解 gold 无法逐位置对齐"的难题。

## §3.4 GRPO 训练

- 组内优势归一化：A_i = (r_i − mean(r))/std(r)，组大小 **G=4**（比 DeepSeek 常用 16 小很多，省采样）
- 标准 GRPO 目标：clip(ε) + KL(π_θ‖π_ref) 惩罚（k3 估计器），KL 权重 β=0.001

## §4.3 实现超参（8×A100 80G）

| 阶段 | 步数/轮数 | lr | batch | 其他 |
|---|---|---|---|---|
| SFT | 1 epoch | 1e-5 | 1/GPU × 8 | — |
| RL(GRPO) | **300 steps** | **1e-6** | 总 64 | G=4, ε=0.2, β=0.001, max_tokens=32,768（训练+推理同配置） |

> **迁移含义⑤**：**RL 阶段非常轻**——仅 300 步、lr 低一个量级。RL 是"精修"不是"再造"（SFT 已给 95% format validity）。我们的 RLVR-P0 应设定为小步数精修协议，监控 SFT 能力是否退化。
> **算力对照**：8×A100-80G（640GB）vs 我们 A10-23GB。但我们占优的两点：①我们的输出是 ~5-13 token 的 L3 链（vs 32K CoT），序列短 3 个量级；②QLoRA 可用。可行配置需 smoke 实测，G 可压到 4-8、max_tokens 数百即可。

## §4.4 结果与消融（对我们校准预期）

| 配置 | FV | 节点F1 | 图F1 |
|---|---|---|---|
| 基座 few-shot（Qwen2.5-Coder-7B） | 0.25 | 0.14 | 0.08 |
| 基座 CoT | 0.41 | 0.22 | 0.10 |
| GPT-4o CoT | 0.92 | 0.50 | 0.29 |
| Claude 3.5 Sonnet CoT | 0.97 | 0.57 | 0.38 |
| **SFT only（代码表示）** | 0.95 | 0.60 | 0.48 |
| SFT only（JSON 表示） | 0.92 | 0.57 | 0.45 |
| **SFT + GRPO（完整）** | **0.97** | **0.62** | **0.51** |

- **RL 增量 = FV +0.02、节点F1 +0.02、图F1 +0.03**——在 SFT 已很强的基础上做结构性收尾（把 95% 的格式合法推到 97%，把结构类错误最后压掉）。**RL 不是主力军，是特种兵。**
- 7B 训练模型全面超过 GPT-4o/Claude 3.5/3.7 的 CoT 提示（图级 F1 0.51 vs 0.29-0.38）。
- 端到端（无 V_cand，embedding 检索）：ComfyBench pass rate **0.67**，超 ComfyAgent（GPT-4o 多智能体）0.56 共 11 个点。

## 对 RLVR-P0 的直接行动清单（从本笔记导出）

1. 奖励采用 **veto 分层**：硬门（词表合法/DAG 合法/可选 I/O 粗契约）一票否决 → 连续层只用 **set_f1**；顺序/边信息不进奖励（绕开多解 gold 对齐问题，靠 SFT 先验携带）。
2. EOS/长度类 shaping **第一轮不做**（phantom advantage 风险 + ComfyUI-R1 证明纯结构门+召回已够）。
3. 数据增广抄作业：**gold 链 + 80% 干扰 L3 候选集**构造多采样样本（同时服务 M3 prompt 设计）。
4. 协议量级：GRPO G=4-8、~300 步、lr 1e-6、KL β=0.001、clip ε=0.2 起步；RL 前必须有 SFT 冷启动（M3-P1/P2-T1 checkpoint 即是）。
5. 预期校准：RL 定位为**结构性收尾**（格式/结构类错误的最后压制），预期增量几个点而非质变；主增益仍来自 SFT 数据侧（与我们"约束在数据侧"的既有结论一致）。
6. 评测协议可借鉴 WorFEval 的 **LIS（最长链）+ MCIS（最大公共子图）** 双层指标——我们 set_f1（集）+ LCS（序）的双指标结构与之同构，无需改。
