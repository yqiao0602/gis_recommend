## 判读

1. **组件层信息全部在场且不弱**：操作集合（0.913）、局部转移（0.904）、长度分箱（0.628 vs 0.389）、
   末操作（0.626 vs 0.352）——Task 文本确实编码了"做哪些操作、什么和什么相连、大致多长"。
2. **缺口精确定位在"组装"**：组件可预测性（AUC 0.90+）与完整序列表现（0.499）之间的落差，
   不是 Task understanding 或 Operation semantics 的缺失，而是
   **把局部正确的转移拼成全局一致序列** 的监督不足/能力未形成。
3. **首操作为零信号是结构性的**（永远是 provisioning 惯例），不构成问题；
   末操作有真信号（目标决定收尾）。
4. **对应 owner 的 W3-a/b/c/d 分层预判**：本审计给出 b 强 / c 强（局部）/ d 弱——
   即 **"GEE 数据能教 task understanding 与 operation 语义与局部依赖，
   但不足以监督完整 workflow construction"成立**，支持"分层 Workflow Reasoning"重设计方向；
   无需推翻 GEE 在 Route-2 中的角色。

## 局限

- 线性探针是信息下界；LLM 可提取更多——但训练后模型在完整序列上（0.499）反而低于
  组件探针的 AUC（0.90+），**落差本身就是发现**。
- family/长度标签来自池子结构化 plan（自动分层产物）；长度分箱 11+ 类的探针数 1,242（足够）。
- 未做 seq2seq 形式的信息论估计（H(sequence|task)）；组件探针已足够回答本次裁定问题。
