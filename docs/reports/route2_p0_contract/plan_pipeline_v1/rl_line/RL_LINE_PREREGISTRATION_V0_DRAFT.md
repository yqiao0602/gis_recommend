## 1. 设计原则（含两处已确认的机制修正）

- **P1 GRPO ≠ 去偏**（对早期"组内相对自动对消偏差"说法的修正）：组内归一化只消
  **加性共模偏移**；与候选内容相关的评分偏差（如偏爱长计划/高频家族）会被组内比较当作
  "质量差异"**强化**。去偏职责 = 奖励验证 + 置信门控，与 GRPO 分工不互替。
- **P2 RAFT 不能创造验证器看不见的正确性**：同任务全体候选共有的缺陷会通过筛选被
  训练得更稳定。RAFT 首轮限定可核验错误类型。
- **P3 单变量纪律**：E1–E7 每级只改一个模块；底座、数据切分、采样预算、评测口径全程固定。
- **P4 奖励分量分开记录**：合成分数的权重预注册；不可核验的分量从第一版起**屏蔽（masked）**，
  不猜测、不强打分（B2-P1 审计的 unverifiable 类即先例）。
- **P5 成功标准 = 预注册验收条件**，非 loss、非单一 reward 上升。

## 3. 四阶段总览与 E0–E7 阶梯

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| Phase 1 | GRPO 工程 smoke + 奖励模块验证（§4） | §4 工程验收全过，**不证能力** |
| Phase 2 | RAFT / DPO 低风险对照（§5） | 与 E0 对照的预注册读数 |
| Phase 3 | 亲和采样 + 门控 GRPO 主实验（§6） | 依赖并行线交付可信子集/多解结论 |
| Phase 4 | 过程奖励 / 估计增强消融（§7） | Phase 3 结果可解释后 |

| 实验 | 训练方法 | 回答的问题 |
|---|---|---|
| E0 | 当前 checkpoint，不训练（复用既有预测） | 基线是多少 |
| E1 | RAFT + SFT | 筛选候选回灌是否有效 |
| E2 | DPO | 明确偏好对能否改善错误区分 |
| E3 | 基础 GRPO + 结构奖励 | 在线优化能否改善结构错误 |
| E4 | GRPO + 置信门控 | 不可靠反馈降权是否有额外收益 |
| E5 | E4 + 失败模式/亲和分层采样 | 定向组织训练任务是否进一步改善 |
| E6 | E5 + 分项过程奖励 | 阶段级反馈能否改善阶段选择与计数 |
| E7 | 最优稳定基线 + Kalman/其他估计增强 | 优势估计改进是否有独立收益 |

E1/E2 可独立分支；E3–E7 按依赖逐级。每级观测统一为：parse 率、阶段遗漏率（X4）、
臆造率（X5）、重复计数错误率（X6）、under-emit、harmful-extra、平均长度、held-out 对照集
表现——**禁止只看总 reward**。

## 4. Phase 1：GRPO 工程 smoke（可执行核心）

- **规模**：24 任务（16–32 区间中值，OQ-1）× k=8 rollouts；按 taskType × target 长度带分层，
  seed 20261013。
- **奖励 v0（全 gold-free，四分量分开落盘）**：
  - r1 schema/parse：JSON 可解析、必需字段齐全；
  - r2 词表封闭：全部 stage token ∈ 训练词表；
  - r3 重复合法：repeat 为正整数且符合折叠语义；**计数不可核验的任务维度直接 masked**；
  - r4 结构有效：相邻折叠后序列合法（无空序列/非法定义）。
  - 合成 = 加权求和，权重预注册（OQ-2，建议等权起步）；逐分量值必须单独落盘。
- **步骤**：
  - S1 环境/数据核验：SHA 对账、adapter 指纹、`nvidia-smi` 共租检查；
  - S2 纯评分干跑（24×8，不更新）：产出奖励分布、**组内有效差异率**、全同组原因登记、
    parse 率、吞吐 tokens/s——本步即管线正确性证据；
  - S3 单步 GRPO：梯度有限性、adapter 保存/重载字节校验；
  - S4 短程训练（固定步数或 24 任务 2–3 epoch，OQ-4）：run_ledger 全记录；
  - S5 恢复测试（中断→断点续跑）+ 资源峰值记录。
- **KL**：对冻结 init 策略，β 初值 0.04（OQ-3）。
- **工程验收（全过 = PASS，不作能力声明）**：S2 存在 ≥1 个有效组内差异组；全链零事故；
  恢复测试通过；吞吐数字落盘；账本/SHA 齐全。

## 5. Phase 2：RAFT / DPO 低风险对照（纲要）

- **RAFT**：候选过 r1–r4 门槛回灌 SFT（P0 训练配方复用）；首轮限可核验维度（X5 捏造、
  格式、连接断裂；计数仅取任务文本明确指定的子集）。依据 P2 原则不得把"过结构筛选"
  等同于"正确工作流"。
- **DPO**：chosen=合法完整 vs rejected=含可判定缺陷；先只建 gold-free 维度偏好对；
  不为凑算法数量扩展数据工程。DPO 非绝对免疫标签噪声：合理替代工作流不得标 rejected。
- **评估**：固定 held-out 训练池切片作对照，禁止只观察训练样本改善。

## 6. Phase 3：亲和采样 + 门控 GRPO（纲要，依赖外部输入）

- **亲和 v0** = 把 CAPLOC 失败分解（X4/X5/X6 判定）跑在训练池子样本上 → **失败模式分层
  采样框**（无需新建探针）；策略探针亲和（直接/先分解/依赖优先/生成后自检）作为正式仪器
  在本阶段引入。
- **任务适配奖励分量（r5 需求覆盖）上线前置条件 = 并行线交付可信 dev 子集 + 多解判别
  结论**；未交付前 r5 不上线（P1 原则：GRPO 不是去偏器，r5 必须建立在已去偏的判定上）。
- 先跑普通 GRPO 基线，再逐个叠加采样分层、置信门控；分族报告训练前后变化。
- 红线（重申）：亲和标签**不进运行时路由、不直接作奖励加分项**——否则重演 37 类/Oracle
  判决的模板化死法。

## 7. Phase 4：过程奖励与估计增强消融（纲要）

- 分项过程奖励 vs 整体奖励对照（E6）。
- **估计增强（E7）的启动条件 = Phase 3 实测到 GRPO 优势估计不稳定**；在此之前不开。
- 定位：论文贡献级消融（SFT → RAFT/DPO → GRPO → GRPO+估计增强，逐级对照）。
