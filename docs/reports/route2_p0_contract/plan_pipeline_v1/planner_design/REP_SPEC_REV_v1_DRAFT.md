## 0. 本草案要解决的核心问题

字面展开表示 (i) 没有教模型两件事：**重复的边界在哪里**、**重复了几次**。
P0 的 2-stage 循环失控 = 模型忠实复现"无限交替展开、无终止标记"的金标形态。
本规范修订让"重复什么 / 重复几次 / 按什么顺序 / 何时结束"成为**显式监督信号**。

## 1. 重复语义六要素（每个重复结构必须可回答）

| 要素 | 定义 |
|---|---|
| 重复单元 | 单个 stage，或一段**有序 stage 序列**（pattern） |
| 重复次数 | `repeat_count` = 总执行轮数（非"初次+重复"） |
| 轮内顺序 | pattern 内 stage 顺序必须保留 |
| 终止边界 | 重复单元结束后衔接的后续 stage 显式存在 |
| 数据依赖 | 下一轮输入是否依赖上一轮输出（语义元数据，不改变序列形态） |
| 次数不一致 | 不同 stage 实际执行次数不同时，**禁止**强行赋予相同 repeat |

## 2. 目标 JSON 语义（字段名示意，落地前与 expand(stages) 约定统一）

```json
{
  "repetition_groups": [
    {"pattern": ["AGGREGATION", "RASTER_LOAD"],
     "repeat_count": 24,
     "order_preserved": true}
  ],
  "stages": [
    {"seq": 1, "family": "AGGREGATION"},
    {"seq": 2, "family": "RASTER_LOAD"},
    {"seq": 3, "family": "BAND_ARITHMETIC"}
  ]
}
```

语义：前两个 stage 构成有序重复单元，执行 24 轮后进入 BAND_ARITHMETIC。
`stages` 数组在目标表示中为**去重后的单元序列**（非字面展开），长度 = 去重后步数；
`repeat_count` 显式承载重复次数。

## 3. 折叠规则（从 raw 链重建时）

1. **相邻同 family 连发** → 单 stage `repeat=N`（语义层折叠；禁止机械连发展开）
2. **交替循环窗（如 A→B ×24）** → pattern=[A,B], repeat_count=24 的重复组；
   stages 表达为去重单元序列（A, B, [后续…])
3. **合并审查（owner 特别警告）**：尾部同 family 连发**不得**仅凭 family 相同就合并——
   若对应不同数据对象/依赖，必须保留为独立 stage。折叠必须保留任务所需信息。
4. 循环窗与连发同时存在时，先切分最大重复单元，再逐段折叠
