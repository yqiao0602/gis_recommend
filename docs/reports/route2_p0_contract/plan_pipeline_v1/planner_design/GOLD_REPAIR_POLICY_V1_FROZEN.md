# Gold 修复政策 v1（正式版，owner 确认 2026-10-12）

状态：**FROZEN**——核心原则经 owner 确认生效；"全量 Gold 修复"与"可信 dev 冻结"为两个独立关口。

## 核心结论（政策基础）

蓝图 repeat = 上游语义链相邻同族 RLE 机械计数：**不能直接作为循环次数监督；也不能反向一律展开**。
机械上发生了折叠 ≠ 每个折叠都应展开为多阶段——若上游链本身把条件/迭代/抽象操作编码为重复 token，
展开只是把上游表示缺陷搬到下游。

## distinct_call_collapse 粒度门槛（操作化）

| 判断 | 处置 |
|---|---|
| 多个 API 调用共同完成一个逻辑操作（如构造过滤条件再应用到集合：`ee.Filter.lt` + `ee.ImageCollection.filter`） | 保留一个 Workflow 阶段，repeat=1；不把内部 API 调用拆成多阶段 |
| 多个独立过滤/变换操作，分别作用于数据并形成可区分处理步骤 | 按原序拆成多阶段，各阶段 repeat=1 |
| 多个阈值判断属于同一分类任务、只是不同类别规则（如连续 `ee.Image.where`） | 优先视为一个逻辑分类阶段中的多条规则；不以 where 重复次数决定阶段数 |
| 调用关系/参数/数据流不足以区分 | 暂不改写，标记 `unresolved_granularity`，不纳入可信 dev |

**all_distinct 触发粒度审查，不自动展开。**

## 生效边界

- 本政策用于逐例裁定。**不授权**对 1,437 个 all_distinct 批量展开；**不授权**把 repeat>1 统一改成 repeat=1。
- 每个修复必须保留：原值、修复值、理由、证据定位。
- 修复副本与原件永远并存；变更输出差异清单，不覆盖冻结文件。
- 无源码/参数证据的案例保留待核验，不强给二元结论。

## 语义判定与数据变更分离（owner 裁定）

- `semantic_ruling`（诊断轴）与 `repair_action`（变更轴）独立记录；诊断标签升级不触发数据改写。
- all_identical ≠ 循环：同方法名可对应不同条件/阈值/输入（canonical 无参数）。

## 可信 dev 子集准入（严格口径）

1. Gold 语义经人工或充分证据验证；
2. 关键阶段顺序与重复语义无未解决歧义（含 unresolved_granularity 排除）；
3. 无未解决 binding error；
4. 相同/近重复 Workflow 不造成不合理重复计权。
报告须含：原始 dev 与可信 dev 双指标、样本数、剔除原因、各家族覆盖率；可信子集不得只剩简单短链。

## 评测安排

P1+P3 完成后双评测现有预测（原始 Gold vs 可信 Gold）；差距 = 原指标受 Gold 表示问题影响的量化；
随后对修复样本小规模对照，再决定是否重训。目的：把"模型能力不足"与"监督标签表达不当"分开。
