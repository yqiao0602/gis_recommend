# R3-PLANNER-P1 设计比较文档（v1，2026-10-03，CPU-only 设计与误差画像，未训练）

> 依据 owner 裁定：先做 A/B/C 三方案单变量设计比较，**不放行训练**；倾向 B（预算）优先。
> P0 基线冻结（后续所有 P1 结果只与它比）：M1 1.0000 / M2 0.6448 / M3 0.5027 / M4±1 0.5231。
> 本文档新增：P0 全量误差画像（n=3,705 parsed 行），用于让 A/B/C 的选择有数据依据。

## 1. P0 误差画像（新增分析）

### 1.1 长度偏差呈双峰：中位精确 + 严重低估尾部

| 指标 | 值 |
|---|---|
| bias（pred−gold）mean / p50 | **−3.07 / 0** |
| 严重低估（<−2 步）行占比 | **23.6%** |

中位行完全精确——均值被长尾拖偏。**B 的预期收益集中在 23.6% 的尾部行。**

### 1.2 计数饱和曲线（关键）：误差随 gold 计数单调恶化

| gold_count | n | mean bias | exact |
|---|---|---|---|
| 1 | 7,761 | −0.11 | **0.70** |
| 2 | 2,473 | −0.68 | 0.28 |
| 3 | 907 | −1.29 | 0.18 |
| 5 | 238 | −2.89 | 0.03 |
| 10 | 56 | −6.80 | 0.05 |
| 20 | 12 | −17.33 | 0.08 |
| ≥50 | ~20 | −25 ~ −365 | 0 |

**计数预测在 1-3 处饱和**——无论 gold 多大，模型倾向输出小计数。这是
**"计数回归任务欠训练"的教科书形态**（P0 每 count 值在 1.69M tokens 里几乎只见一次）。
另：gold_count=0 的槽位（模型多报的 family）n=3,891 ≈ **1.05 个虚报 family/行**。

### 1.3 Per-family：高计数 family 最差

SPATIAL_FILTER exact 0.36（−1.14）、AGGREGATION 0.11（−1.15）、THRESHOLD_LOGIC 0.07（−2.26）。
**不是"读不懂格式"**（parse 100%、count=1 命中 70%）——是**量级学习不足**。

## 2. 三方案单变量定义与比较

| 方案 | 唯一变量 | 其余 | 成本 | 针对的误差形态 | 风险 |
|---|---|---|---|---|---|
| **P1-A 格式显著化** | counts/length 的表达更醒目（如 "×N" 后缀、字段前置） | 同 P0 | ~9h GPU | 若模型"读"字段有问题 | parse 1.0 + count=1 命中 0.70 说明**不是读的问题**——预期收益低 |
| **P1-B 预算提升** | **2-4 epoch**（1.69M→3.4-6.8M tokens），其余完全冻结 | 同 P0 | 18-36h GPU | **饱和曲线（1.2 节）**——欠训练回归的标准解法；与 R3-B-1 token-阈值假说同向 | 低（最坏 = 确认预算不足够了） |
| **P1-C 计数加权** | count/length 错误的 loss 上调 | 同 P0 | ~9-18h GPU | 虚报 family + 计数饱和 | 与 B 混合会破坏归因；先 C 会把"欠训练"与"权重"混淆 |

## 3. 推荐（基于误差画像，与 owner 倾向一致）

**顺序：P1-B（2 epoch 起步）→ 若 M3 仍 <0.7 → P1-C（加权）→ A 仅在 parse/格式异常时考虑。**

- B 的数据依据：饱和曲线 + 双峰长度 + W2 的 token-阈值先例，三个证据同向。
- **成功判据**（对照 P0 基线）：M3 0.50→≥0.65 且 M2 不降（±0.02 内）且 M4±1 0.52→≥0.65。
- **失败判据**：2/4 epoch 后饱和曲线形态不变 → 欠训练解释被否定，转 P1-C。
- epoch 数建议：先 2 epoch（≈18h，tokens 3.4M）；若趋势好但未达标，同一 adapter 续 2 epoch
  （resume 机制，免重训）到 4 epoch——保持单变量内的预算阶梯。

## 4. 边界

- P1 全程不改 Schema v1、不改冻结 Stage-1 v2_2 主线与 gate、不碰 RL/Stage-2。
- P0 基线（M1-M4）为唯一对照基线；结果报告沿用同一 eval 脚本与 held-out 集。
- 训练放行归 owner（本文档仅为设计比较 + 误差画像）。
