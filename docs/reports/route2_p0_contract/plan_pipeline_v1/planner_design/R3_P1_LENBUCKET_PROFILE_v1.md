## 2. 决定性发现：长 workflow 的"长度"几乎全部由重复构成，而 distinct 阶段数恒定

- **gold_distinct_mean 在所有桶恒定 ~2.9-4.5**：51+ 步的 workflow 也只用 ~4.4 种 family。
- **repeat_share 随长度单调上升到 95.1%**：51+ 桶的长度 95% 来自同族重复。
- Planner 的 pred family 数与 gold distinct 基本一致——**它已经学会了"阶段结构"，
  学不会的只是"重复次数"这个数字**。
- 深尾 bias（−189）不是回归误差，是**表示缺失**：任务文本与 Plan 里都没有
  "为什么是 300 次"的可学习依据（次数由数据性质决定，如波段数/类别数/年份跨度）。

## 3. 裁定：owner 倾向的第二种解释成立——这是表示问题，不是曝光问题

1. **P1-C 的数值加权/重采样无法解决深尾**：在"次数不可从 Task 文本识别"的前提下，
   加权只是让模型更用力地猜一个不可识别的数字。
2. **P0→P1-B 的分桶对照**：预算提升只改善了 1-12 步桶（F1 +2~+4pp，bias 收窄），
   51+ 桶 F1 0.127→0.141、bias 几乎不动——**预算假说在深尾已被否定**。
3. **正确方向（与 owner 预判一致）**：**Blueprint v2 把重复结构显式化**
   （loop 分组/迭代标记），并把**量级解析移出 Planner**——
   Planner 负责"结构 + 阶段 + 循环分组"（它学得好的部分），
   "循环多少次"由 Serializer/Grounding 阶段从实际数据上下文解析（Stage-2 正好有数据）。
   这与两阶段架构天然衔接。
4. **M3（绝对计数精确率）作为 Planner 指标的定位应降级**：
   它测的是一个从输入不可识别的量；替代指标 = 阶段集合/循环分组正确率 + 长度粗分箱
   （信息阶梯已证明可预测）。

## 4. 附带发现

- 1-5 桶 P1-B 出现 pred_max=865 的离群生成（gold ≤5）——偶发 runaway，
  生成端可加长度 sanity clamp（诊断工具层面，非冻结物）。
- 1-5 桶 bias +1.04/+1.10（轻微过报）：短任务反而多报——与深尾欠报合成
  "向典型长度回归"的完整画像，进一步证实条件信息不足。

## 5. 建议（供 owner 裁定）

1. **暂停 P1-C 数值加权**（本画像即前置裁定依据）。
2. **启动 Blueprint v2 设计**（CPU）：以原始链（pre-RLE）的游程结构为蓝本，
   schema v2 = 阶段序列 + 重复分组（循环体 + 迭代标记）；
   量级数字从 Planner 目标中移除，改为粗分箱或交由 Serializer/Grounding。
3. 评测口径相应调整（M3 绝对计数 → 分组/结构正确率 + 长度粗分箱），**冻结 gate 不动**，
   新口径仅作 Planner 线诊断。
