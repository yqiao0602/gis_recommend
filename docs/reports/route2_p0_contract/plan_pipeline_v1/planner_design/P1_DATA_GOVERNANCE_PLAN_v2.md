# P1 数据治理计划 v2（2026-10-11，owner 裁定更新，替代 v1 数据构造方案中与本文冲突的部分）

## 假设更新（三层次区分，非因果结论）

> **机制假设（待验证）**：P0 循环失控可能来自训练目标对合法重复模式的**过度展开**，
> 以及**重复语义与终止边界的监督不足**；解码策略可能放大该问题。

| 层次 | 证据 | 可结论 |
|---|---|---|
| 任务语义 | 抽检 10/20 行有多期/逐年/分区需求 | 重复处理可能正确 |
| 金标表达 | 循环存在但 repetition_group 声明缺失 | **序列与重复元数据可能系统性不一致** |
| 模型生成 | P0 输出 2-stage 窗口至 token 上限 | 学到了长循环模式；终止失败原因待验证（×2 对照实验：`重复延续集` vs `重复终止集`） |

关键保留：真实迭代需求 ≠ 金标每次重复都正确；声明缺失 ≠ 必须截断。展开次数由
Planner-v2 表示规范决定，不由任务是否有迭代语义决定。

## 数据处理方案 v2（替代 v1 中 ×2/×3 过采样与统一补声明）

- **A 类**：按 Planner-v2 正式表示规范补全重复语义；**禁止**机械地把每个重复窗口
  映射为一个 repetition_group——先核对重复范围、次数与 stages 表达一致性
- **C 类**：回查 G0 `gee_canonical_chain` 与原始脚本；无法确认者**不进定向修复集**、
  不推断循环次数、不截断
- **重复样本 ×2–3 过采样：暂缓**——先统计训练集内合法重复/未声明重复/正常终止的
  实际比例与分布，再定采样权重（避免放大长循环倾向）

## 执行序列（顺序固定）

1. **完成 133 行证据审计**：C 类回查原始脚本；对其余未抽检样本分批审查；
   "任务需要重复处理"与"金标显式展开次数合理"**分别判定**
2. **训练集终止行为统计**：正常终止样本 vs 合法重复样本的长度分布、重复窗口
   频率、声明覆盖率、序列长度与触顶关系
3. **P0 失败预测逐例对齐金标**：定位模型偏离起点——金标本含长循环 vs
   金标结束后模型继续重复（两者训练修正不同）
4. **构造 P1 定向数据**：完整基线保留；只修高置信度样本；加"合法重复且正常
   结束"对照 + "重复一次即可覆盖多对象"对照；全部修改带来源/理由/置信度

## 诊断对比集（正式 P1 训练前构建，直接检验机制假设）

- **重复延续集**：金标确实要求多次重复同一窗口
- **重复终止集**：任务需迭代处理，但表示应在重复边界/聚合步骤处结束
- 分别测：重复次数偏差、正确终止率、完整性、JSON 合法率
- 判读：第一类能正确重复、第二类持续循环 → 支持"终止边界监督不足"假设，
  P1 方向由此确定
