# PCA 协议 v1.1 版本化修订 — B 组任务表述处理规则（2026-10-13）

> 性质：对 `PCA_PROTOCOL_V1_FROZEN.md` 的**版本化补充修订**（owner 指令，2026-10-13）。
> v1.1 不改变三臂设计、指标、判读树、冻结账本要求；只细化 §2.1 B 组任务表述的处理规则，
> 并记录 owner 对 B 组候选的逐条裁定。
> **背景（构念偏差发现）**：B 组候选源 `v2a_A_dev.jsonl` 的 `task_text` 多为"已有脚本的
> 工作流说明"（"It first repairs geometries … then …"式叙述、工具名、参数级步骤顺序），
> 而非待解决的用户任务。原样送入模型会把我方要测的"根据任务目标规划工作流"变成"从工作流
> 说明中提取步骤"——这不是关键词泄露，而是评测构念偏差。正式生成前必须修正。

## 1. B 组任务表述处理规则（owner 五条，全量采纳）

1. **原始材料只读归档**：原始 `task_text`、原始金标链（processes/links）、来源信息
   全部保留、只读，永不直接送入模型。
2. **独立的目标导向评测表述**：为每个入选任务生成改写稿——保留分析目标、输入数据类型、
   必要业务约束、输出要求；删除原文直接给出解法的过程性叙述（步骤顺序、算法名、参数级
   流程、工具名称）。
3. **禁提供现成解法**：模型输入不含原始脚本流程、算子链、现成操作顺序。
4. **改写质检**：改写稿须重新检查（a）任务仍可解；（b）未引入原任务没有的假设；
   （c）存在多个合理路线时金标可容纳。
5. **逐条入账**：原文、改写稿、修改理由、owner 审核结果逐条记录于
   `pca_b_group_restatement_v1.md`；最终实际送入模型的任务文本以 SHA 冻结。

**边界（owner 强调）**：去过程化不得把任务改得过于宽泛（如只说"分析城市环境"）——
改写稿必须保留足够的分析目标、数据条件与输出要求，否则低分将无法与"任务欠定义"区分。

**报告纪律**：任何报告中不得把改写后的输入描述成"未经处理的原始 dev-120 任务文本"；
须表述为"源自 dev-120 任务 WXXXXXX 的目标导向改写表述（PCA v1.1 规则）"。
