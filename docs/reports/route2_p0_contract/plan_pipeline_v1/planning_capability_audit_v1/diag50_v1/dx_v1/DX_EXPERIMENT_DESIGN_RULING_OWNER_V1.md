# DX 实验设计裁定（Owner，2026-10-17）V1 — A1/A2/B 单变量分离

> 来源：owner 会话裁定全文归档（逐字，见下）。本裁定是对同日《DX 研究路线裁定 V1》中
> 「S2 能力诊断三组条件对照」的**细化与扩展**：三条件表（原始卡/补全卡/补全卡+S2 专项训练）
> 演化为 **A1（卡片补全）/ A2（检索语料升级）/ B（规划能力对照）** 三个单变量实验，
> 并新增 A1×A2 组合效果后测与「三态区分」测量协议。

## Owner 裁定原文（逐字归档）

这个纠正非常关键。它改变了我们对 DX-50 当前瓶颈的判断：S1 虽然覆盖了全部 1,291 个算子，
但目前检索的主要是算子 ID 的词面相似性，而不是算子的实际 GIS 功能。

因此，我们现在不能把 S2 的弃权简单归因于模型能力不足，也不能直接认定正确算子是被语义
检索漏掉的。当前至少有三个需要分别验证的问题：

1. S1 检索问题： 使用 `layer_c_intent.text` 后，Top-10 是否能更好地覆盖适用算子？
2. S2 知识问题： 在候选算子已经进入 Top-10 的情况下，补全功能描述、参数和输入输出信息，
   是否能改善选择？
3. 规划模型问题： 即使给模型正确的算子候选和完整卡片，它是否仍然遗漏必要步骤、错误组织
   依赖或提前终止？

我建议按下面的方式推进。

| 实验 | 固定条件 | 唯一主要变量 | 要回答的问题 |
| --- | --- | --- | --- |
| A1：卡片补全 | 冻结 S1 检索文本、Top-10、模型及提示词 | S2 可见的算子卡片 | 完整知识能否改善选择？ |
| A2：检索语料升级 | 冻结模型、提示词、卡片版本及 Top-K | 算子 ID 文本 vs. `layer_c_intent.text` | 功能语义能否改善候选覆盖？ |
| B：规划能力对照 | 冻结独立测试集及评价规则 | 基础模型 vs. 不同训练版本 | GEE 数据训练是否真的提升任务规划？ |

这里还有一个很重要的实验细节：A1 和 A2 最好先分别进行，再测试组合效果。
否则，如果检索语料和卡片同时改变，即使最终表现提高，也无法判断改善究竟来自哪里。

对于 A2，建议至少记录：

- Top-10 是否包含经人工审查确认的可行算子；
- 可行算子的排名及检索分数；
- 正确选择率、错误选择率和合理弃权率；
- 不同算子类别、不同任务复杂度下的表现。

还要区分「算子在库中」「算子被 Top-10 召回」和「算子卡片足以证明它适用」这三种情况，
它们不是一回事。

我的最终建议：保留当前冻结基线，先执行已经批准的 OTB 卡片补全；同时准备功能描述驱动的
S1 独立对照实验，但不要静默修改现有检索逻辑。 规划模型训练则继续独立推进，避免把检索和
知识库的问题误当成模型规划能力不足。

这次纠正实际上帮我们明确了一个重要原则：在判断模型是否真正学会 GIS 任务规划之前，必须
先控制好它获得的候选算子和算子知识质量。否则，最终的工作流错误可能来自规划、检索或知识
表达中的任何一层。

## 登记：与既有裁定的关系（Claude 登记，非 owner 原文）

1. **对「三条件对照」的细化**：原条件 2（补全卡）→ A1；原「S1 语料升级另立受控变更」
   （路线裁定附加仪器发现节）→ 正式升格为独立实验 A2；原条件 3（补全卡+S2 专项训练）
   的训练判定后移到 A1 结果之后（推进顺序第④步不变）。组合臂（补卡×意图检索）在 A1、A2
   各自完成后才允许运行——单变量归因优先于组合效果。
2. **三态区分并入测量协议**（细化③重建基线的四分类）：
   - 算子在库中 ∧ 未被召回 → 检索缺失（A2 的测量对象）；
   - 算子被召回 ∧ 卡片不足以证明适用 → 卡片证据不足（A1 的测量对象）；
   - 卡片足以证明适用 ∧ 仍未选/错选 → 真选择错误（模型层；B 及 S2 训练判定的对象）。
   「算子在库」不再可作为「候选可见」的证据——与 owner 63 行终审尺度一致
   （候选中有相似工具 ≠ 候选中有足够完成任务的工具）。
3. **A2 记录要求**（在路线裁定「记录候选集是否包含经人工确认的可行算子」之上扩展）：
   可行算子是否入 Top-10、其排名与检索分数、正确/错误/合理弃权率、按算子类别与任务
   复杂度分层。三种情况分记，不合并分子。
4. **A1 执行约束（从"冻结 S1 检索文本、Top-10"导出）**：补卡后的 S2 pack 必须复用
   dx50_full_v1 冻结 retrieval.json 的 Top-10（不重跑 S1）；卡片是唯一变量。
   与「P0 补卡禁止写顶层 description 键」交叉风险守卫一致——该守卫同时保护 A1 边界
   与冻结基线。
5. **执行序（与推进顺序①→④对齐）**：已放行的 OTB 115 卡补全 = A1 的证据底座（①），
   先行；A2 的检索语料对照在其后独立运行（②仪器线）；B 臂（Base vs 训练版本）独立推进，
   不以 A1/A2 结果为前提。
