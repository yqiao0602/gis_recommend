# S1 分层扩审计设计 V1（2026-10-18，owner 批准）

- **目标**：把 B/C 合格训练样本从 113 行扩到 **5k–10k 行**（分阶段，非硬指标）；
  审计单位为**任务组组件**，逐行登记结果；不启用 S2（规则治理全量）。
- **前提**：正式 B/C 训练集继续冻结；本设计不改变任何准入结论。

## 1. 分层维度（组件级）

| 维度 | 层 | 说明 |
| --- | --- | --- |
| split | train / val / test | 沿用 V2，不得为凑量破坏组件级划分 |
| 模板支持度 | high(>100) / mid(11–100) / low(2–10) / singleton(1) | 按组件主导 RLE 模板的池内支持度 |
| 工作流长度 | short(1–5) / medium(6–20) / long(21+) | 组件中位 RLE 步数；长链单独保覆盖 |
| 任务类型 | 前 10 类 + other | 单类配额上限 20%，防常见任务挤占 |
| 治理风险（抽样时计算） | 空/极短 RLE、UI 脚手架、重复块、已知 Q1/Q2、间接资产引用 | 复用 Q2 机械扫描器；仅对抽样组件计算 |

## 3. 抽样与配额（Phase 1）

- **单位**：组件；抽中组件的全部行一起审计（组件内相似行不重复计为独立证据）。
- **总量（Phase 1 配额）**：train 6,133 组件 / val 758 / test 671（合计 7,562 组件；见
  `B_TRACK_S1_AUDIT_QUOTAS_V1.json`）。
- **预期合格率**：以 221 行试点估计 70.1%（A/C1/M）→ Phase 1 预计 **≈5,300 合格行**
  （train 4,299 / val 531 / test 470）。
- **层内分配**：按各 split 内（支持度×长度×任务类型）组件数比例分配，并施加：
  - 长链（≥21 步）≥ 配额 20%；test 长链 ≥30%；另设 ≥30 步子集 ≥10%；
  - singleton + low 支持合计 ≥ 配额 40%（检验低支持缺口）；
  - 单任务类型 ≤ 配额 20%；
  - high 支持 ≥ 配额 10%（保持常见模式覆盖）。
- **Phase 2**：仅在 Phase 1 合格率/覆盖达标后扩容至 **10k 合格行**；不自动启动。

## 4. 审计判定

- 组件级：先判结构与关系（沿用 Q2 关系三分）；组件内逐行按六桶准入（A/C1/C2/M/Q1/Q2）。
- 记录：`component_id / split / strata / sample_ids / bucket / status / exclusion_reason /
  evidence / adjudicator / provisional`。
- 证据：源码行锚点；外部证据（WorldPop 单位、GEE 数据定义等）单独挂账，不阻塞抽样。
- 复核：owner 按层抽查 ≥10%；agent 判读标 `provisional`。

## 5. 与 A 组的公平比较

- A、B、C 使用**同一底层任务组划分**与**同一准入任务池**；
- A 不得只做随机缩减：须按 B/C 的分层分布做**匹配对照**，并报告样本量/任务组/任务类型/链长/排除原因；
- test 固定，所有臂同一测试任务；不得用 test 调整治理规则。

## 6. 配额表与交付

- 机器可读配额：`B_TRACK_S1_AUDIT_QUOTAS_V1.json`（按 split×层给出目标组件数与上限）。
- 交付顺序：①本设计 → ②抽样清单（组件 ID+层）→ ③逐行审计结果 → ④合格率/覆盖报告 →
  ⑤ABC 样本清单 V2 → ⑥评估器/配置冻结 → ⑦owner 启动令。
