## 3. 策展流程（阶段二执行）

1. **选样冻结**：本清单 24 组 → 数据治理账本登记（sample_id / task_group_id）。
2. **L0 固化**：脚本全文 + 内容哈希 + 源码路径；`GOVERNANCE_CHANGE_LOG_V1.md` 记录。
3. **L1 起草**：逐条填写 goal / necessary_steps / dependencies / branches / stop_conditions /
   alternatives；每步带 `script:line` 证据。**起草者不得引入源码中不存在的步骤。**
4. **L2 映射**：逐步骤填 API/参数/数据版本/阈值（含单位与数据集值定义）/适用条件/证据。
5. **L3 保真度**：沿用 Q2 判定；新发现入变更账本。
6. **交叉审查**：另一人（owner 或独立 agent）逐条核对证据；不符则退回。
7. **准入**：按治理规范 §3 落桶；产出 `TRUSTED_REFERENCE_SET_V1`。
8. **验收**：每条记录可通过 §5 四问追溯；抽查 ≥20%。

## 4. 与阶段三/四的接口

- 阶段三（评估集）：从同一任务组池中按 §8 划分规则抽出独立 test；候选矩阵本身不
  进入 test（防泄漏），评估集另建。
- 阶段四（三组对照）：
  - A = 原始序列 SFT（现有监督，基线）；
  - B = 审核后序列 SFT（本参考集 + 高置信样本）；
  - C = 审核后双层表示监督（L1+L2+L4，同一任务集合与预算）。
- 判据 = 独立评估集的规划指标（必要步骤召回/约束覆盖/依赖正确性/有害步骤/长链退化/
  多参考可用性），不以标签相似度替代。
