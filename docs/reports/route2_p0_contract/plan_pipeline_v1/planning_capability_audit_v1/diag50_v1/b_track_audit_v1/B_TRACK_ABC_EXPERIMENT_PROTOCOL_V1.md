| 组 | 数据/监督 | 回答的问题 |
| --- | --- | --- |
| A 原始序列 | 现有原始工作流序列监督（未治理） | 现有数据与监督方式能达到什么基线？ |

## 2. 冻结的控制条件

1. **划分一致**：A/B/C 共用 `B_TRACK_SPLIT_MANIFEST_V1`（组件/独立组原子；同侧约束）。
2. **测试集独立**：不参与训练、模型选择、阈值调整、治理规则迭代。
3. **训练条件可比**：同一基座、同一训练预算、同一解码设置、同一评估程序；若某项必须不同，提前登记。
4. **数据构成可追溯**：记录各组纳入/排除/改变表示的**任务组清单**与计数，不只报性能。
5. **多参考纪律**：当前 28/29 条 `multiref_of` 为空——**不得为提升指标把未获准样本临时变为多参考**；多参考可用性只报告资格状态，不计入主指标。

## 3. 指标（先冻结定义，阈值待 owner 批准）

**主指标**（规划正确性）：
- 必要步骤召回率（necessary-step recall）；
- 任务约束覆盖率（时间/区域/指标/数据/输出条件）；
- 依赖关系正确性（顺序与数据流）。

**共同门（co-gates，不得以主指标提升换取）**：
- 有害/多余步骤率（harmful/extra steps）；
- 长链退化（长工作流的步骤遗漏与依赖错误是否增加）。

**辅助指标**：
- 解析/格式健康（parse、invalid、hit_cap、termination）；
- 精确序列匹配率（保留但**不作唯一主指标**）；
- 多参考可用性（当前仅报告 eligibility）。

**建议阈值（待 owner 批准）**：主指标 +5pp；co-gate 不劣化 >3pp；解析不下降 >5pp；无投机行为（空工作流、相邻重复、未链接步骤）。未获批准前，阈值栏为 `pending_owner`。

## 4. 评估集规则

- 使用独立测试 split（`B_TRACK_SPLIT_MANIFEST_V1` 的 test 单元）；
- 近重复/共享脚本组已合并为同侧，不跨集合；
- 评估前锁定预测哈希；评估后不得回头调参再报同一测试集；
- 报告任务级与候选级分布，不只报均值。

## 5. 启动与停止

- 启动前置：owner 批准协议与阈值；训练数据构建完成并版本化；划分清单冻结；
- 停止条件：任一 co-gate 破线、解析显著退化、空工作流/重复率异常上升、训练不稳定；
- 结论表述：即使 C 无提升，也应区分"双层表示无收益 / 治理或样本规模影响 / 实验设计问题"，不得笼统归因。
