## 1. 单位与不变量

1. **组件不变**：沿用 V2 的 `component`（近重复指令 J≥0.75 + 共享脚本 ID 的连通分量）。
   本 pass 不拆分、不重建组件。
2. **族 = 组件的连通分量**：边只来自本规范判定为 `merge` 的候选对。
3. **行跟随组件、组件跟随族**：同一组件、同一族的所有行必须落在同一 split。
4. **V2 只读**：不覆盖 `B_TRACK_SPLIT_MANIFEST_V2.json`；V3 另存。

## 2. 组件特征（证据轴）

| 轴 | 提取方式 | 用途 |
| --- | --- | --- |
| 文本标题 | 指令首行 `Task:` 之后；小写、词干化、去停用词 | 目标对象 + 目的 |
| 正文相似度 | 全指令稀有词（df≤60）Jaccard；组件内取前 8 条指令对的最大值 | 文本证据 |
| 来源数据 | 指令中的数据族正则 + 脚本 `ee.*('ASSET')` 字面资产；资产族前缀映射 | 来源证据 |
| 目标对象 | 标题词 − 停用词 − 目的动词 − 泛化词 | 目标证据 |
| 处理目的 | 标题中首个目的动词/名词 → 6 类：detect / analyze / generate / compare / visualize / export | 目的证据 |
| 输出类型 | 规范链尾 + 指令关键词 → image_export / table_export / chart / map_view | 输出证据 |
| 结构 | `semantic_chain_rle` 的步序列与多重集 | 实现证据 |

**词干化**只做轻量规则：`ies→y`、复数 `s/es` 去除；`is/us/ss` 结尾不处理。
**目的兼容**：同一目的类，或任一方为空；`detect` 与 `analyze` **不**自动视为兼容。

## 3. 候选发现（discovery，不决定合并）

任一信号成立即进入候选；相似度只用于发现：

| 信号 | 规则 |
| --- | --- |
| D1 正文 | 稀有词 Jaccard ≥ 0.45 且共享稀有词 ≥ 3 |
| D2 标题 | 两条指令标题共享 ≥ 2 个标题词（df≤1500）且标题 Jaccard ≥ 0.40；token-pair 倒排。桶 ≤40 逐对；桶 >40 用确定性锚点做星型聚类（见 §4.5）；大桶处理上限 30,000、星组上限 50,000，超出跳过并记录 |
| D3 资产组 | 完全相同的字面资产集签名（≥2 个资产）作为一个**组级**候选；组内按 G1 整体裁决，不逐对枚举 |
| D4 结构 | RLE 模板完全相同且标题 Jaccard ≥ 0.35；单桶 >100 组件跳过并记录 |
| D5 数据族+目标 | 共享数据族且共享**稀有目标词**（目标词 df≤100）；单桶 >10 组件跳过并记录 |
| D6 完全相同标题 | 归一化标题完全相同的组件成组（锚点→成员，O(n)）；这是最强的同族证据 |

**跳过的高频桶必须记录**（键、组件数），在验收报告中说明覆盖限制。

## 4. 判定规则（按顺序）

设 `T`=标题 Jaccard，`B`=正文稀有词 Jaccard，`O`=共享目标词数，
`DF`=共享数据族数，`AS`=共享字面资产数，`A`=资产集合 Jaccard，
`CS`=RLE 完全相同，`P`=目的兼容，`TT`=任务类型相同。

### 4.1 保持分离（先判）

| 规则 | 条件 |
| --- | --- |
| K1 目的冲突 | `P=false` 且 `O=0` 且 `B<0.50` |
| K2 目标/来源均无交集 | `O=0` 且 `DF=0` 且 `AS=0` 且 `B<0.50` 且 `T<0.60` |
| K3 仅结构相似 | `TT=false` 且 `DF=0` 且 `AS=0` 且 `T<0.40` 且 `B<0.50` |

### 4.2 合并（任一成立）

| 规则 | 条件 |
| --- | --- |
| M1 相同资产集 | `AS≥3` 且 `A≥0.60` 且 `T≥0.25` 且（`O≥1` 或 `T≥0.50`） |
| M2 标题+来源 | `T≥0.60` 且（`AS≥1` 或（`DF≥2` 且 `T≥0.70`））且 `P` 且（`O≥1` 或 `AS≥1`） |
| M3 正文+资产 | `B≥0.60` 且 `AS≥1` 且 `T≥0.25` |
| M4 目标+数据族 | `O≥2` 且 `DF≥1` 且 `P` 且 `T≥0.40` |
| M5 结构+标题 | `CS` 且 `T≥0.50` 且 `P` 且 `TT` |
| M6 近同标题 | `T≥0.75` 且 `P` |
| M7 正文强相似 | `B≥0.70` 且 `T≥0.40` |

### 4.3 待人工裁决

候选成立但不满足 K1–K3、也不满足 M1–M7 → `pending`。Pending 边**不合并**；
**跨 split 的 pending 逐条进入台账**（`pending_edges_cross_split`），其余 pending 在
决策日志中逐条记录并在台账按规则汇总。由 owner/审计员裁决。
若 pending 规模超过候选的 25%，暂停并回报，不放宽阈值。

### 4.4 组级规则（G1 资产集组）

完全相同的字面资产集签名（≥2 个资产）形成一个组，不逐对枚举（避免组合爆炸）：

- 组内**按目的类分层**（空目的类自成一类）；
- 每层选确定性锚点（前 20 个中使到层首 10 + 层尾 10 的平均标题 J 最大者）；
- 成员条件：**标题 J ≥ 0.50 或共享目标词 ≥ 2**；
- 有成员 → 该目的层 `merge`；无成员 → `keep_separate`，记录 `G1_incoherent_group`；
- 合并层以锚点到成员的有序边进入决策日志（O(n)，非 O(n²)）；
- 每个（资产集签名 × 目的类）层在台账 `asset_set_groups` 中有一条组级记录
  （成员数、资产集、目的类、锚点、合并数、判定与依据）。

**为什么按目的分层**：同一资产集可能同时支撑 “识别油膜” 与 “分析油膜光谱” 两类目的；
整组合并会因目的冲突或目标交集为空而整体放弃，导致同族漏合并。分层后各自裁决。

### 4.5 星型规则（D2 大标题桶）

标题 token-pair 桶 >40 个组件时，不逐对枚举：

- **按目的类分层**（空目的类自成一类），每层独立成星，避免跨目的合并；
- 每层在排序后的前 20 个组件中选**确定性锚点**：使锚点到固定样本（层首 10 + 层尾 10）
  的平均标题 Jaccard 最大（并列取组件 ID 最小）；
- 锚点到成员的条件：**标题 Jaccard ≥ 0.50 或共享目标词 ≥ 2**（目的类已同层，天然兼容）；
- 满足条件者生成 `D2_star_group` 合并边（锚点→成员，O(n)），组记录入台账
  `title_star_groups`；不满足者不合并；
- 大桶处理上限 30,000 个；星组总数上限 50,000；超出后的大桶跳过并记录，属于已知覆盖限制。

## 5. 族构建与一致性审计

1. **T1 优先（原子同标题组）**：`T1`（完全相同归一化标题）的组边先合并，
   **不设上限**——同标题组件绝不跨族。
2. **G1/D2 组边**按证据强度降序加入；若合并后族组件数 > **10,000**，跳过该边并记入
   `family_assignment_deferred`（不合并，逐条保留证据）。族由 T1 原子组 +
   不超过上限的 G1/D2 合并构成。
3. 只有 `T1/G1/D2` 组边参与族构造；`M2/M4/M5/M6/M7` 只作为**逐对判定**记录在
   决策日志，不进入族构造。原因：对全量边做传递闭包会产生 47,217 组件的跨主题
   长链（农业用地/碳损失/气温/NDVI/城市树冠被串成一族），截断又会丢弃 1.1 万条
   高置信度边。T1 优先 + 上限合并是保守且可解释的替代。
4. 族 ID = `F` + `sha1(排序后的组件 ID 列表)[:16]`（确定性）。
5. 一致性审计（只报告，不自动拆族——拆族可能重新引入泄漏）：
   - `heterogeneous`：族内出现 >1 目的类且目标词交集为空；
   - `oversized`：族内组件 > 200；
   - `weak_chain`：族 > 50 且族内最弱合并边 `T<0.30` 且无共享资产/数据族。
4. 上述族保留为**一个 split 单元**，标记 `review_required`，在验收报告中单列。

## 6. Split V3 规则

- 以**族**为单位，用 seed **20261018** 洗牌，按族数 80/10/10 分配 `train/val/test`；
  与 V2 的 80/10/10 组件规则保持同构，只把单元从组件换成族。
- 每行继承其族 split；组件原子性与近重复约束自动保持。
- 记录：代码 SHA、池 SHA、V2 manifest SHA、族映射 SHA、V3 split SHA。
- 报告 V2→V3 的族数、组件数、行数、各 split 变化，以及被合并的跨 split 家族清单。

## 7. 验收条件（对应 owner 要求）

1. 所有被识别（候选）的同族关系都有处置记录（merge / keep_separate / pending）；
2. 不存在**未处置的高置信度跨 split 同族冲突**：所有 `merge` 前的跨 split 边必须
   并入同族；所有 `pending` 跨 split 边与 `family_assignment_deferred` 高置信度边必须显式列出；
3. 组件原子性、近重复约束保持（0 违反）；
4. V3 可复现：代码、输入池、任务族映射、split 各自有版本与哈希；
5. V2 保留不覆盖，报告 V2→V3 差异；
6. 明确声明：一次扫描不能证明不存在任何潜在语义泄漏。

## 8. 已知限制

- 文本相似度是词面/稀有词层面，不是语义模型；同义改写可能漏检（森林退化案例已
  靠资产+目标+数据族捕获，但其他领域可能仍漏）；
- 资产提取只覆盖 `ee.*constructor('literal')`；动态拼接、模块导入、`ee.data` 读取
  的资产不可见；
- 代表指令用于标题/目的；一个组件内多指令的极端分歧可能被低估（特征取并集补偿）；
- 24/7,562 个抽样组件缺本地源码，资产轴不可判；
- 族一致性审计是启发式，`review_required` 族必须人工复核后才能冻结。
