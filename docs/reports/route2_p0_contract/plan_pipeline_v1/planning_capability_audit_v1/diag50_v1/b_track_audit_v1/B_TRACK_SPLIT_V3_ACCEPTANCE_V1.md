## 3. 构造规则（为什么不是并查集）

全量逐对 `merge` 图在**任何阈值**下都存在跨主题长链：全部边并查集得到 **47,217
组件**的单一连通分量（农业用地、碳损失、气温、NDVI、城市树冠被串在一起）；即使
`T≥0.80` 仍有 1,391 组件的簇。按 1,000/2,000 上限截断会丢弃 **1.1 万条高置信度边**。

V3 采用保守替代：

1. **T1 优先**：归一化标题完全相同的边先合并，**不设上限**；同标题组件绝不跨族。
2. **G1（相同资产集）+ D2（标题星）**按证据强度降序合并，族上限 **10,000**；
   超限边记入 `family_assignment_deferred`（不合并、逐条留证）。
3. `M1/M2/M4/M5/M6/M7` 仅作为逐对判定记录在决策日志，**不进入族构造**。

## 10. 覆盖限制

1. 标题/正文是词面相似度，不是语义模型；同义改写可能漏检；
2. 资产提取只覆盖 `ee.*constructor('literal')`；拼接、模块导入、`ee.data` 资产不可见；
3. 353 条脚本引用（24 个抽样组件的代表脚本）本地缺失，资产轴不可判；
4. 结构候选跳过 84 个 >100 组件的 RLE 桶（最大 1,348），数据族+目标跳过 1,888 个
   >10 组件的桶；均在台账 `skipped_buckets` 记录；
5. 一次扫描**不能**证明不存在任何潜在语义泄漏。
