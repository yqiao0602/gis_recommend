# B_TRACK_TWO_LAYER_REPRESENTATION_SPEC_V1（双层表示规范 V1）

- **日期**：2026-10-18；**状态**：设计规范 V1（owner 定位：B 双层表示=主方向，
  证据支持的设计方向、**非已验证方案**——须经小规模对照实验检验）
- **配套**：`B_TRACK_DATA_GOVERNANCE_SPEC_V1.md`（准入与可追溯）、
  `B_TRACK_TRUSTED_REFERENCE_SET_V0_SCOPING.md`（参考集选样）

## 0. 非目标（先写清楚，防止走回老路）

1. **不是**把原始 GEE 脚本压缩成一条更精细的标签序列。此前已证明：仅把工作流转成
   抽象语义序列会丢失大量信息（Route-2 四块合璧：Oracle 语义链→QGIS 贴合度崩塌）。
2. **不是**为 30 类 RLE 扩词表。Q2 证据指向"字面量层承载语义"，扩词表解决不了
   阈值/版本/时间范围。
3. **不是**放弃原始实现层。原始脚本、API 调用、参数与源码位置必须完整保留（可追溯、
   可复核、避免不可逆抽象损失）。
4. **不是**已获实验验证的训练方案。V1 只冻结数据结构与监督边界；有效性归阶段四。

## 1. 三层数据结构

### L0 原始实现层（Raw implementation layer）——保留事实

- 内容：原始 GEE 脚本全文、API 调用序列（`gee_canonical_chain`）、数据资产 ID、
  波段、阈值、时间范围、参数、输出、必要的代码上下文与源码定位（`script_id` + 行号 +
  内容哈希）。
- 作用：唯一事实源；任何上层结论必须可回落到此层。
- 不变式：**L0 永不改写**。上游修订（如指令修正）只能新增版本引用，不覆盖原脚本。

### L1 规划语义层（Planning semantic layer）——表达分析逻辑

- 内容：任务目标、必要分析步骤（necessary steps）、步骤间依赖（dependency）、
  数据流、条件分支、停止条件、**合理替代实现（multi-reference）**。
- 作用：让模型学习"为什么需要这些步骤、它们如何组织"，与具体平台实现解耦。
- 已冻结约定：
  - 必要步骤 = 缺少即无法达成任务目标的步骤（证据=源码中承担该目标的调用链）；
  - 依赖分字段（顺序 ≠ 依赖；提不到标 unknown，禁伪造——沿用 Stage-1 信息合同）；
  - 多参考并列，不选唯一答案；每条参考带适用条件。

### L2 条件与实现映射层（Condition–implementation mapping layer）——保留差异

- 内容：规划步骤 ↔ 具体 API/参数/数据版本/阈值/平台实现的映射；每条映射带
  **适用条件**（数据版本、传感器、时间窗、区域、阈值语义）与**证据来源**（源码位置）。
- 作用：在抽象规划与具体执行之间建立可检查映射；承载"同一规划、不同实现"的合法
  多解与"同一 API、不同语义"的差异（如 `lte(0)` vs `lte(-0.02)`）。

### L3 保真度层（Fidelity layer）——独立于上述三层

- 内容：指令与源码的一致性判定（失实/欠描述/忠实/不可判）、证据、置信度、
  注释-代码矛盾标记、单位/数量/阈值的核对结果。
- 作用：**不把注释当成实际执行行为**；保真度缺陷不得转化为规划结构标签。

### L4 监督层（Supervision layer）——训练时如何用前三层

- 规划监督：L1 必要步骤 + 依赖 + 条件分支；
- 条件监督：L2 适用条件字段（参数语义以数据集值定义为准）；
- 保真度监督：L3 仅作为**样本准入闸门与损失掩码**，不作为生成目标（不让模型学写
  任务描述）。
- **硬规则**：L3=失实的样本不得作为高置信规划监督（隔离）；L3=欠描述只可用于
  "缺项被标注"的条件化样本。

## 2. Q2 案例如何映射（规范的可执行性检验）

### DIFF-19（阈值差异在 RLE 中不可见）

- L0：script_73545 / script_73548 全文 + 行级定位；
- L1：两侧**同一高层流程**（NBR 差值→水/云掩膜→阈值→面积）；
- L2：两条映射——A `postNBR.lte(0)`；B `postNBR.lte(-0.02)`，各带适用条件与源码行；
- L3：A 脚本注释写 -0.02 而代码为 0（注释-代码矛盾，保真度缺陷记录，A 判欠描述）；
- L4：不拆成两条规划链；阈值差异只进 L2；注释不进监督。
- **判读**：这解决 owner 指出的问题——"不把不同阈值误判成不同规划结构"。

### DIFF-4（同目标两种合法实现）

- L0：script_111047 / script_111048；
- L1：同一目标（五类分类）；必要步骤集合相同（采样→训练→分类→精度→面积）；
- L2：A=逐类像元采样+三分割+验证/测试矩阵；B=sampleRegions 全样本+训练集混淆矩阵；
  两条映射各带适用条件（是否需要留出验证、样本量约束）；
- L3：两指令均未述验证协议（欠描述，标注而非否定）；
- L4：多参考并列，模型应学"何时用哪种"；不得因参考脚本只有一种实现而把另一种判错。

### DIFF-6（UI 挂件造成 4 个伪标签）

- L0：script_213853 / script_213841；
- L1：核心氮含量流程相同；A 多一个交互探索挂件（非分析步骤）；
- L2：挂件映射归入"实现与脚手架"子层，显式标记 `non_analytical=true`；
- L3：A 指令欠描述挂件（记录）；
- L4：挂件调用**不进入规划监督**（A 类治理：ui.*/调试输出剥离），但仍在 L0/L2 可追溯。

### SAME-15（同码双描述，目标变量失实）

- L0：两侧逐字节相同；
- L1：同一规划（冠层/生物量回归流程——以源码为准：生物量）；
- L2：目标变量 = biomass（源码三处自证）；
- L3：A 指令写 canopy height = **失实**；B 忠实；
- L4：A 侧样本隔离（不得作为高置信训练），B 侧可入；**不是**"两个不同的规划结构"。

## 3. 最小记录 schema（可信参考样本 V1）

每条参考样本记录至少包含（JSON）：

```json
{
  "sample_id": "...", "task_group_id": "...",
  "task_description": "...",
  "raw": {"script_ids": ["..."], "source_hashes": ["..."], "source_paths": ["..."],
          "canonical_chain": "...", "rle": "..."},
  "planning": {
    "goal": "...",
    "necessary_steps": [{"id": "p1", "intent": "...", "evidence": "script:line"}],
    "dependencies": [["p1","p2"]],
    "branches": [], "stop_conditions": [],
    "alternative_implementations": [{"alt_id": "...", "applies_when": "..."}]
  },
  "conditions": [{"planning_step": "p1", "api": "...", "params": {...},
                  "data_version": "...", "threshold": {"value": 0, "unit": "...", "semantics": "..."},
                  "applies_when": "...", "evidence": "script:line"}],
  "fidelity": {"verdict": "忠实|欠描述|失实|不可判", "issues": [...], "evidence": [...],
               "confidence": "高|中|低", "adjudicator": "owner|agent-delegated",
               "provisional": true},
  "admission": {"bucket": "A|C1|C2|M|Q1|Q2", "governance_version": "B_TRACK_GOVERNANCE_V1"},
  "mapping": {"raw_to_planning": [...], "planning_to_conditions": [...]},
  "provenance": {"created": "2026-10-18", "rules_version": "...", "commit": "..."}
}
```

字段要求：每个 `necessary_step` 必须有源码证据；每个条件必须有适用条件；fidelity 必须
带 adjudicator 与 provisional 标记；多参考必须各带 `applies_when`。

## 4. 与现有表示的兼容与迁移

- RLE 保留为**诊断/检索/对齐**用轻量视图（不是监督目标本身）；
- canonical chain 保留为 L0 的派生视图；
- 现有 SFT 序列监督 = 阶段四实验组 A（基线），不改动；
- 双层表示监督 = 实验组 C，仅在高置信样本子集上构建，任务集合与 B 组一致。

## 5. 有效性主张边界（写进论文/报告时必须保留）

- 双层表示解决"稳定分析逻辑 vs 依条件变化的实现细节分开监督"；
- 它**不**自动修正失实描述、不自动补全缺失步骤、不自动消除训练分布偏置；
- 是否提升规划能力 = 阶段四实验问题，判据为独立评估集上的规划指标（必要步骤召回、
  约束覆盖、依赖正确性、有害步骤、长链退化、多参考可用性），**不是**标签相似度。
