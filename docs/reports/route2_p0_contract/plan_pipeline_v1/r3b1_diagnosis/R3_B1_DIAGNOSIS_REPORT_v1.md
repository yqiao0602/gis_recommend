## F1. W2 探针的真实结构——类型对兼容性问题，Tier 无关（推翻本诊断的一个预设）

W2 的 783 个 dev 探针**不是从任务/Plan 派生的**，而是类型级问题：
`Operation 1 "…" produces T1. Operation 2 "…" accepts T2. Can 2 consume 1? Yes/No`。
共 **34 个不同 (produces→accepts) 类型对，其中 8 个为 Yes 型**（探针数 602/181）；
783 题中 775 题（99%）的 gold 严格等于"类型相同→Yes"规则（8 题例外待查，不影响结论）。
**含义**：探针构成与 Tier 无关，双臂差异 100% 来自模型行为——A/B×Yes/No 的探针侧交叉表不存在。

## F5. W2-Yes 崩溃的解释收敛——证据转向"累计 token 量阈值"假说

配对预测分析（同一批 783 题）：

| gold | A-only 预测分布 | A+B ep2 预测分布 |
|---|---|---|
| Yes（610） | **空 407 / No 202 / Yes 1** | Yes 456 / No 116 / 空 38 |
| No（173） | No 156 / 空 17 | No 172 / 空 1 |

- A-only 不是"把 Yes 判成 No"，而是**对合法转移大面积拒答（407 空）+ 否定（202）**；
  对非法转移则相当自信（No 0.9017）——判别器只学到了单向边界。
- **累计 token 曲线**（Yes 类准确率 vs 训练累计 tokens）：
  A+B ep1 = 0.216 @ 24.7M → A+B ep2 = 0.748 @ 49.4M → A-only = 0.0016 @ **14.3M**。
  A-only 的 tokens 恰好低于 A+B ep1 的水平，而 Yes-mapping 的出现发生在 24.7M→49.4M 区间。
- 结合 F4 的反例（主 Yes 对覆盖充足），**owner 的"可能 B：训练分布/规模效应"目前证据更强**：
  Yes-mapping 更像是随累计训练量在某阈值后涌现的能力，而非 Tier B 的内容独有信号。
- **判别性预测（供未来决策，不在本轮执行）**：若对 A-only 数据训满 2 epoch（累计 ~28.6M，
  跨入涌现区间）后 Yes-mapping 出现 → 量变假说成立；若仍 ≈0 → 内容/竞争假说复活。
  此为 12h 级 GPU 实验，**本轮不做，仅登记预测**。

## F6. TRUNC 截断位置与被截字段（owner 关键问题）

1,766 条构建期截断行（逐行用与 builder 一致的 tokenizer 公式复算，行数与报告精确吻合）：

| 指标 | 值 |
|---|---|
| 保留文本比例 | **p50 = 69.4%**（中位丢约 31% 文本），mean 60% |
| 丢失整步数 | **p50 = 8 步**，p90 = 44，mean 30.6 |
| **丢失 ≥1 个含约束（constraints）步骤的行** | **70.1%** |
| 丢失最终 EXPORT_OUTPUT 步的行 | 仅 1.0% |
| 丢失分支步骤 | 0（池子 plan 已线性化，depends_on 均为线性） |
| 被截尾部最后一步的 family（top） | COLLECTION_MGMT 938 / SPATIAL_FILTER 182 / BAND_SELECT 160 / AGGREGATION 139 |

**回答 owner 的问题**：截断不是只砍无害尾巴——**70% 的被截行丢掉了含约束的步骤**，
中位即丢 8 个整步、三成文本；但最终导出步很少被砍（长 Plan 的末段多是集合管理/过滤类步骤）。
截断伤害的核心 = **约束信息与中后段步骤的监督**，而非"结果导出缺失"。
