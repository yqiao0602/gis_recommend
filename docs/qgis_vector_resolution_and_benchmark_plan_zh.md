# QGIS 矢量处理补强与横向评测待办

日期：2026-06-02

## 1. 当前判断

当前系统已经能跑通：

```text
自然语言任务 -> L3 工作流 -> QGIS 算子链
```

但主要剩余问题收敛为两类：

1. **传统矢量 / QGIS-native 流程能力不足**  
   模型在 GEE/遥感栅格任务上表现较好，但遇到 buffer、clip、dissolve、spatial join、reproject、fix geometry、nearest、voronoi、create grid 等传统矢量任务时，容易套用遥感栅格模板。

2. **复杂任务细节完整性不足**  
   模型常能给出正确规划骨架，但会漏掉关键细节，例如阈值方法、云掩膜、矢量化/栅格化、分区统计、导出、专用算法步骤等。

这两天优先解决第一类问题：**矢量处理流程能力不足**。随后再做总体横向评测。

## 2. 两天内优先目标

目标不是立即重训大模型，而是先形成一个可验证的矢量处理补强方案：

```text
高质量矢量任务样本
  -> 结构化任务表示
  -> 正确 L3 矢量流程
  -> QGIS 算子链
  -> 好链 / 坏链 preference 对
  -> 小模型或候选排序模块补强
  -> 横向评测
```

核心判断标准：

- 矢量任务不再被错误带到遥感/栅格模板；
- 关键矢量步骤覆盖率提升；
- QGIS 算子链更贴合任务，而不是只给通用安全模板；
- 与 LLM-only、LLM+RAG、当前系统相比，完整方案有可量化提升。

## 3. 待办事项

### A. 构建矢量任务评测集

先准备一批 30-50 条矢量/QGIS-native 任务，覆盖：

| 类别 | 示例任务 |
|---|---|
| 缓冲区分析 | 道路缓冲、医院服务范围、河流保护区 |
| 裁剪与叠加 | 按研究区裁剪地块、洪水范围叠加道路 |
| 几何处理 | 修复地块几何、简化河流线、提取建筑中心点 |
| 空间连接 | 监测站连接行政区、学校服务区统计人口 |
| 属性筛选 | 按表达式筛选地块、按字段导出要素 |
| CRS / 投影 | 监测点重投影、不同投影边界合并 |
| QGIS-native | rasterize、polygonize、create grid、heatmap、voronoi、nearest |

每条任务至少记录：

```text
任务描述
任务类型
数据模态：vector / raster / mixed
必须包含的关键步骤
可接受的 QGIS 算子链
明显错误链示例
```

### B. 构建好链 / 坏链 preference 样本

针对每条任务构造偏好对：

```text
好链：buffer -> clip -> dissolve
坏链：select bands -> raster calculator -> clip raster
```

偏好样本重点覆盖：

- 矢量任务 vs 栅格模板错误；
- 缺关键步骤；
- 顺序错误；
- 过度通用模板；
- QGIS 原生算子是否必要。

### C. 调整 QGIS landing / reranker

优先做轻量修复，不急着重训：

- 对矢量任务强惩罚栅格模板；
- 对任务关键词强匹配关键 QGIS 算子；
- 对 buffer / clip / dissolve / join / reproject / fix geometry 等任务必要步骤加覆盖评分；
- 对过度通用模板加轻微惩罚；
- 对 GraphRAG 查到的输入输出类型和常见组合加证据权重。

### D. 设计横向对比实验

同一批任务，对比以下方案：

| 方法 | 说明 |
|---|---|
| LLM-only | 直接让 LLM 输出 QGIS 算子链 |
| LLM + RAG | 给 LLM 提供 QGIS 算子/图谱证据后输出 |
| 当前系统 | 小模型输出 L3 + 当前 QGIS landing |
| 改进系统 | 小模型 + QGIS 矢量补强 + GraphRAG/LLM 证据约束修正 |

统一评价指标：

| 指标 | 含义 |
|---|---|
| 任务意图正确率 | 是否理解任务要做什么 |
| 关键步骤覆盖率 | 必要步骤是否出现 |
| 模态正确率 | 矢量/栅格是否选对 |
| QGIS 算子合法率 | 算子是否存在于 QGIS 算子库 |
| 顺序合理性 | 工作流顺序是否合理 |
| 模板化程度 | 是否过度落到少数通用链 |
| 人工等级 | A / A-B / B / B-C / C |

## 4. 推荐执行顺序

### 第 1 天

1. 整理 30-50 条矢量/QGIS-native 任务；
2. 为每条任务标注关键步骤和可接受 QGIS 链；
3. 跑当前系统，记录失败类型；
4. 构造第一批好链 / 坏链 preference 样本。

### 第 2 天

1. 调整 QGIS landing / reranker 的矢量任务评分；
2. 增加 GraphRAG/LLM 证据约束补全规则；
3. 对同一批任务跑横向对比；
4. 输出总表和人工审查结论。

## 5. 成功标准

短期成功不要求彻底解决所有 QGIS-native 任务，而是证明方向有效：

- 矢量任务的模态错误明显下降；
- buffer / clip / dissolve / join / reproject 等关键步骤覆盖率提升；
- 改进系统相对当前系统在人工 A/A-B 或 B 及以上比例上有提升；
- 相比 LLM-only，系统能减少不存在算子、流程跳步和泛化错误；
- LLM 的作用被限定在任务结构化、证据约束补全、候选解释和输出交互，而不是无约束最终裁判。
