## 1. 背景与问题

GISAgentBench（执行层基准，349 个来自 GIS Stack Exchange 的真实任务、128 工具接口、六区域真实数据、确定性容差判分）提出了双层指标范式：

- **严格成功率 TSR**：结构检查全过 + 每个值在容差内（绝对 1e-6 + 相对 0.01%），二值无部分分——回答"结果能不能直接用"。
- **量化接近度 QCS**：数值（1−sMAPE）、分类（加权 F1）、空间几何（实体级 F1）的接近度聚合——回答"没做对时差多远"。

其六模型（3 闭源 + 3 开源，均为前沿模型 + 完整工具环境）TSR 均值 0.238、最佳 0.327；QCS 普遍为 TSR 的 2–3 倍，失败集中在规划层（漏操作 28.3% + 顺序颠倒 18.4% + 冗余重做 14.4% + 错工具 13.4%），单调用内部错误仅 7.8%。

我们要回答两个问题：① 这套指标设计能否引入我们的论文；② 我们当前最佳 F1 0.2236（基座版对照）是否"太低"。

## 2. 指标映射：他们的设计 ↔ 我们的现状

我们的评测对象是**规划层**（自然语言任务 → 算子链 + 依赖结构），没有数值输出文件，QCS 的数值口径不能照搬；但其**分层设计模式**已有现成对应物：

| GISAgentBench 指标 | 我们的对应物 | 状态 | 证据 |
|---|---|---|---|
| 严格成功率 TSR（二值） | Graph Exact Match（整链完全一致） | 已有 | `SCORES_v1.json` graph_exact_match_rate |
| 量化接近度 QCS（部分分） | Operator micro-F1 / set recall | 已有 | 同上 + 逐行 set recall 诊断 |
| 轨迹接近度（仅诊断，不进主分） | 首步正确率、召回过半行数 | 已有但散在诊断字段，未正式化 | `STAGE_SUMMARY_M1_M3_v1.md` |
| 失败机制归类（预注册固定分类表） | 失控/空图/首步错/无 EOS 分类 | 已有雏形（M3-P1 的 8 个失败做过 6+2 分类） | `m3_p1_sft_v1` 诊断 |
| 行覆盖率 | 桥接覆盖率（bridge drop 率） | 已有，未作为正式指标 | dev smoke "bridge drop 29/33" 记录 |
| 拒答/安全维度 | refusal accuracy、unsafe planning rate | **对方没有，我们独有** | refusal_12 场景 |
| 依赖结构（边级） | edge F1 | **对方没有（只比输出文件），我们独有** | `SCORES_v1.json` edge_micro_f1 |
| 任务难度预标注（caveat × 失败验证） | 无直接对应（task_type/OOD 归因可类比） | 待设计 | Phase 0-B 归因框架可迁移 |
| 成本统计（耗时/token） | mean ops、runaway 行数 | 部分 | 各 SCORES diagnostics |

## 3. 建议引入的三项设计（论文写作层面）

1. **双层主指标正式化**：把"Graph EM（严格）vs Operator micro-F1 + set recall（接近）"定义为论文的主指标对，采用 TSR/QCS 的表述范式。单报 micro-F1 是自我矮化——set recall 0.27、首步 43% 能展示部分能力已经出现。
2. **失败机制分类表升格**：从临时诊断升级为预注册的固定分类表（漏步骤 / 顺序错误 / 复读失控 / 空输出 / 覆盖外输出 / 首步错），与 GISAgentBench 的失败机制表对齐呈现，突出"失败集中在规划层"的共鸣结论。
3. **定位区分声明**：明确写出我们与 GISAgentBench 的互补关系——他们评执行层（工具调用 + 输出文件比对，模型生成参考解 + 专家复核），我们评规划层（算子链 + 依赖结构 + 拒答，真实用户工作流来源 + 确定性结构判分 + 来源隔离防泄漏）。这同时是回应"与已有工作区别"的审稿预案。

## 4. 当前 0.2236 的定位分析

**参照系修正**：0.2236 是我们自己的 9B 基座微调模型在全新基准上的读数，不是与 SOTA 的比较。GISAgentBench 上六个前沿大模型（带完整工具环境）TSR 均值 0.238、最佳 0.327——同量级。基准论文的数字用于暴露差距，不用于冲榜。

**两种论文定位下 0.2236 的角色**：

- **定位 A（基准 + 数据管线 + 路线对比）**：0.2236 是 capability boundary 记录值。主张 = "首个来源可溯、判分确定、训练评测来源隔离的 QGIS 工作流规划基准 + 三条模型路线的受控对比"。
- **定位 B（方法，如领域预训练净效应）**：绝对值不重要，delta 才是主张。已有：后训练版 0.1605 → 基座版 0.2236（+39%，单变量隔离）；终止加权 +24%（0.1605→0.1991）；失控 31→13。M2 DAPT 各组正在跑，若给出干净增量则故事完整。

**合法提升路径**（按性价比）：
1. 重复先验数据治理：25.2% 训练行含连续重复算子（最长 60 连），直接压精度；
2. 双口径对照报告：F1 目前在 50 码桥接后计算，桥接丢弃压低读数（首步正确 L3 层 43% vs 桥接层 30%）；补 L3 层口径表，数字更高且更诚实；
3. 解码/终止控制余量（EOS 加权已证有效，停线未触发）；
4. 更大基座（资源允许时）。

## 5. 建议补的实验：前沿模型参照基线

在前沿大模型（API 调用）上跑一遍我们的基准做参照：给定 L3 词表做上下文内规划（zero-shot / few-shot）。
- 若前沿模型也低 → 基准难度获得外部背书，0.2236 有了语境；
- 若前沿模型高 → 说明瓶颈在监督管线而非任务本身，同样是有价值发现。
两头都是论文素材。设计注意：需在 prompt 中提供 L3 词表与输出格式说明；预测同样过 prediction lock 纪律。
